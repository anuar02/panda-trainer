# План доработки prototype-fresh для Codex

27 сентября 2026. Основа — трезвая оценка прототипа со стороны тренера, клиента,
людей разного возраста и пола, а также со стороны продукта.

Цель этапа: не добавлять новые «вау»-функции, а закрыть то, что мешает показать
прототип настоящим тренерам и получить честный ответ «заменит ли это WhatsApp и заметки».

## Правила для исполнителя

- Работать только в `prototype-fresh/`. Исходный `prototype/` не трогать.
- Перед началом прочитать `prototype-fresh/README.md` и `AGENTS.md`.
  Про маскот — `design-exploration/MASCOT-DECISION.md`. Спрайты панды не перерисовывать
  и не генерировать новые.
- В новом JS и CSS **не писать комментарии в коде**: остальной `prototype-fresh` написан без них.
- Архитектура остаётся прежней: классические скрипты, глобальный `Store`
  (`set`, `silent`, `subscribe`, `commit`), действия через `data-act`, листы через `Sheets`.
  Не переносить на фреймворк и не добавлять npm-зависимости без согласования.
- Каждая задача — отдельный коммит с понятным сообщением. После каждой задачи:
  - `node --test prototype-fresh/tests/*.test.cjs` — всё зелёное (сейчас 100/100);
  - снимки Chromium 390×844 и 1440×960 изменённых экранов в `prototype-fresh/review/<задача>/`;
  - раздел в `prototype-fresh/README.md`: что изменилось, как проверить, что не проверено.
- Запуск: `python3 -m http.server 8777 --bind 127.0.0.1` из корня репозитория,
  затем http://127.0.0.1:8777/prototype-fresh/. Если Playwright не находит браузер,
  укажите `executablePath` к установленному Chromium, а не скачивайте новый.
- Сохранённые данные в `localStorage` читаются с валидацией. Старые записи
  не должны ломаться: невалидное игнорируется, валидное без новых полей читается как раньше.
- Доступность: WCAG AA по контрасту, всё управляется с клавиатуры, у иконок-кнопок есть `aria-label`.
- Если задача требует продуктового решения, которого нет в плане, остановиться и записать
  вопрос в раздел «Открытые вопросы» в конце этого файла, а не угадывать.

## 2. Меньше панды, режим «Спокойный интерфейс»

Панда нравится части аудитории и выглядит детской для другой части (например, тренер-мужчина 45 лет,
серьёзный спортсмен). Сейчас её слишком много.

**Новое правило по умолчанию:**

| Место | Сейчас | Должно быть |
| --- | --- | --- |
| Онбординг, приглашение | панда | оставить |
| Пустые состояния | спит или сидит | оставить |
| Завершение тренировки, первое подключение клиента | конфетти + прыжок | оставить |
| Подтверждения, оплата, посещение, голос (`SMALL` в `js/fx.js`) | конфетти + большой палец | убрать празднование; остаётся тост |
| Тосты | лицо панды | лицо только в тостах успеха после празднования; иначе обычная иконка |
| Сводка «Сегодня» | лицо меняет эмоцию | оставить одно спокойное лицо |
| Главная клиента | машущая панда в карточке | оставить |
| Кнопка «Голос» | лицо панды + микрофон | оставить |
| Оверлей удержания голоса | панда слушает | оставить |

**Режим «Спокойный интерфейс»:**

- Переключатель в профиле тренера и в профиле клиента, у каждого свой. Параметр `?calm=1` для демо.
  Хранить в `localStorage` с try/catch, как палитру в `js/visual.js`.
- В этом режиме:
  - нет конфетти и оверлея празднования вообще;
  - нет лиц панды в тостах, сводке и кнопке «Голос» — вместо лица иконка;
  - панда остаётся только в онбординге и пустых состояниях, без циклической анимации (статичная поза);
  - в оверлее голоса вместо панды — иконка микрофона и полосы громкости.
- `prefers-reduced-motion` продолжает отключать движение независимо от режима.

Тесты: unit-тест на `Fx.afterAction` — в спокойном режиме `celebrate` не вызывается;
для `session.confirm` празднования нет и в обычном режиме.
Снимки: «Сегодня», журнал, главная клиента — обычный и спокойный режимы рядом.

## 3. Свои упражнения сохраняются, библиотека больше

Сейчас `state.customExercises` живёт только в памяти (`rememberCustom` в `js/store.js`),
в `DB.exerciseLibrary` 23 упражнения.

- Хранить свои упражнения в `localStorage` под ключом `trainer-prototype:exercises:v1`
  с валидацией, как журнал в `readLog`. Формат: `{ version: 1, items: [{ name, group, bodyweight, unit? }] }`.
- Нормализация для проверки дублей: регистр, `ё`→`е`, лишние пробелы, дефисы.
  «Жим лёжа» и «жим  лежа» — одно упражнение.
- Библиотеку довести примерно до 80 упражнений по группам: ноги, спина, грудь, плечи,
  руки, кор, кардио, мобильность. Добавить поле `aliases` — разговорные названия
  («становая», «бицуха», «присед», «планочка»).
- `VoiceParse` и поиск в `js/flex.js` ищут и по `aliases`.
- В профиле тренера — простой список «Мои упражнения» с удалением. Удаление не трогает
  уже записанные журналы.

Тесты: сохранение и чтение после перезагрузки (эмуляция `localStorage` в vm), отклонение
невалидной записи, дубли после нормализации, голосовой разбор «бицуха 12 на 12» и «присед 80 на 8».

## 4. Программа клиента обновляется по итогам тренировки

Сейчас программы в `DB.programs` общие и адресуются по имени (`DB.programFor(name)`),
поэтому правка программы одного клиента изменила бы её у всех.

**Модель:** копия при записи.

- Новое хранилище `trainer-prototype:client-programs:v1`:
  `{ version: 1, byClient: { [clientId]: { baseName, exercises: [...] , updatedAt } } }`.
- Функция `programForClient(clientId, name)`: если у клиента есть своя копия — вернуть её,
  иначе общий шаблон по имени. Все места, где сейчас используется `DB.programFor`
  для конкретного клиента, перевести на неё. Найти их через `graft callers programFor`
  или `grep -rn programFor prototype-fresh/js`.
- В блоке завершённой тренировки, рядом с `UI.ChangesSummary`, кнопка
  «Обновить программу клиента». Она открывает лист со списком изменений из `Store.logging.changes(cid)`:
  - замена: «Тяга штанги → Тяга гантели»;
  - добавление: «+ Фермерская прогулка, 3 подхода»;
  - пропуск: «Планка — убрать из программы?» (по умолчанию **не** отмечено: пропуск часто разовый);
  - подходы сверх плана: «Приседания: 4 подхода вместо 3?» (по умолчанию не отмечено).
  Каждый пункт — чекбокс. Кнопка «Сохранить в программу <Имя>».
- Прошлые значения (`prev`) для новых упражнений в программе берутся из только что записанных подходов.
- Текст под кнопкой: «Изменится только программа <Имя>. Шаблон «<название>» останется прежним».
- В мини-группе — отдельно для каждого участника.
- Если изменений нет, кнопку не показывать.

Тесты: копия создаётся при первом сохранении; шаблон и программы других клиентов не меняются;
снятые чекбоксы не применяются; повторное сохранение того же не дублирует упражнения;
невалидное хранилище игнорируется.

## 5. Причина для клиента открывать приложение

Клиенту сейчас мало что делать в приложении: на главной в день тренировки написано
«Программа появится позже», и это ничего не сообщает.

- Заменить «Программа появится позже» (места: `js/screens/client.js:68`, `:91`, `:134`,
  `js/sheets.js:363`; у тренера `js/screens/trainer.js:40`, `:290`, `:569`):
  - есть программа — название и первые 3 упражнения, «ещё N»;
  - нет программы — клиенту «Тренер подберёт упражнения на месте»,
    тренеру «Без программы» с действием «Выбрать программу».
- «Прогресс» клиента (`progress()` в `js/screens/client.js`): для каждого упражнения
  лучший вес и повторы, изменение за 4 недели («+10 кг»), простой список без графиков.
  Данные — из сохранённых журналов.
- «История» клиента: у прошедшей тренировки показывать заметки тренера, если он пометил их как видимые
  клиенту, и короткую сводку отличий от программы («заменено 1 · добавлено 2»).
- Видимость заметок: у заметки флаг `shared` (по умолчанию `false`), переключатель в карточке заметки
  в журнале тренера — «Видно клиенту». Голосовые заметки создаются закрытыми.

Тесты: расчёт лучшего результата и прироста, фильтрация закрытых заметок, пустые состояния.

## 6. Полевой режим для проверки голоса против касаний

Гипотеза «голосом быстрее, чем касаниями» не проверена. Нужны данные из настоящего зала.

- Параметр `?field=1` включает запись событий в `localStorage` (`trainer-prototype:field:v1`):
  - голос: время нажатия и отпускания, сырой текст распознавания, разобранные пункты,
    какие пункты тренер убрал перед «Записать», время до «Записать», ошибки распознавания;
  - касания: открытие листа подхода, время до сохранения, использование «Как в прошлый раз».
- В профиле тренера в полевом режиме — «Выгрузить полевой журнал» (JSON-файл) и «Очистить».
- Без `?field=1` ничего не записывается. Данные не уходят на сервер.
- Сводка в выгрузке: среднее время записи одного подхода голосом и касанием,
  доля распознанных фраз без правок.

Тесты: без флага запись не ведётся; сводка считается на синтетических событиях.

## 9. Проект синхронизации (только документ)

Сейчас всё хранится в одном браузере — сломанный телефон означает потерю журнала.
Это главный блокер, но выбор бэкенда — решение владельца продукта. **Ничего не реализовывать.**

Написать `prototype-fresh/SYNC-DESIGN.md`:

- перечень всех ключей `localStorage` в `prototype-fresh` и что в них лежит
  (`SessionRepository`, журналы, палитра, свои упражнения, программы клиентов, полевой журнал);
- сущности и связи: тренер, клиент, занятие, журнал, программа, копия программы клиента, заметка;
- требования: работа без сети в зале, два устройства тренера, клиент видит только своё;
- конфликты: что делать, если журнал правили на двух устройствах;
- 2–3 варианта (например, Supabase, Firebase, свой сервер) с плюсами и минусами для
  частного тренера в Казахстане: цена, хранение данных, офлайн;
- вопросы к владельцу продукта для выбора.
