# Временные видео маскота

29 сентября 2026. Только три акцентных момента в `prototype-fresh`:

- `wave` — приветствие в первом входе тренера.
- `thumbs` — завершение настройки тренера.
- `jump` — существующее празднование результата или подключения.

Источник: `design-exploration/mascot-video-2026-09-28/out/`. Файлы скопированы
без перекодирования и без новой генерации. WebM — прозрачный VP9 без звука;
WebP — fallback для Safari/iOS и браузеров без VP9; PNG — постер.
В каждой точке загружается только выбранный формат. Совокупный размер трёх
комплектов на диске — около 2,5 МиБ, это не объём одной загрузки страницы.

Ролик проигрывается один раз (~5,17 с), затем остаётся постер. Празднование
исчезает через 6,2 с и не перехватывает нажатия. Ошибка загрузки или отказ
автовоспроизведения оставляет постер. При уходе с экрана медиа освобождается;
при перерисовке того же экрана сохраняется текущий элемент и прогресс.

В спокойном режиме и при prefers-reduced-motion используются прежние PNG,
без загрузки WebM/WebP. Смена настройки во время проигрывания останавливает медиа.
Пустые экраны, клиентское приглашение, hero, лица и голосовой интерфейс сохраняют
прежний способ отображения. CSS-анимация тела и реакция на тап отключены у видео.

Размер персонажа выровнен через CSS-кадрирование: границы альфы объединены по
всем 62 кадрам WebP (320×320), с запасом 2 px. В mascot.js CLIPS хранит x/y/w/h:
wave 60/35/207/254, thumbs 66/35/194/254, jump 53/37/230/278.
Постер и видео используют одну геометрию, исходные прозрачные поля не меняются.

Это временные ассеты и образцы движения для будущего Rive-рига. Известный
перескок хвоста в jump сохранён согласно ранее принятому решению.

Проверка: `node prototype-fresh/tests/mascot-video.browser.cjs` при сервере
`python3 -m http.server 8777 --bind 127.0.0.1` из корня репозитория.
Отчёт и снимки: `prototype-fresh/review/12-mascot-video/`.
Safari-ветка проверена с подменой user-agent в Chromium; настоящий Safari/iPhone
не проверялся, установленного Playwright WebKit в окружении нет.
