# Полевой протокол · 2 тренера × 3 тренировки

Проверяем гипотезу: голос сокращает время записи подтверждённого подхода без
роста числа ошибок. Это шесть наблюдений за тренировками, не доказательство
для всей аудитории. Интервью: [тренеры](interview-trainers.md), [клиенты](interview-clients.md).

## Подготовка

1. Получить согласие тренера и присутствующего клиента на наблюдение и запись
   событий. Использовать коды T01/T02 и вымышленные карточки, не диктовать имена
   или сведения о здоровье. Полевой JSON содержит исходные распознанные фразы.
2. Зафиксировать commit прототипа. Открыть его с `?field=1` в доверенном HTTPS
   окружении на телефоне; на компьютере допустим localhost. Обычный HTTP по
   адресу ноутбука в локальной сети может не дать микрофон. Подготовка HTTPS —
   обязанность организатора; прототип сам ничего не разворачивает.
3. В профиле проверить наличие выгрузки, выгрузить пробный JSON, затем очистить
   только полевой журнал. Не очищать чужие журналы тренировок.
4. На каждую наблюдаемую тренировку создать отдельное демо-занятие. Подготовить
   сравнимые упражнения и незаполненные подходы. Завершённые журналы не использовать
   повторно для ввода. Не переносить сюда единственную копию реальных результатов.
5. Дать по две пробные записи каждым способом. Их выгрузить отдельно или очистить
   полевой журнал после обучения. Время обучения не входит в основное сравнение.
6. Проверить обычный/крупный текст и короткое нажатие «Голос» → текст. Настройку
   текста и спокойного режима оставить выбранной самим тренером и зафиксировать.

## Порядок шести наблюдений

Разделить чётное число сопоставимых подходов пополам. При нечётном количестве
последний пометить вне сравнения. Сопоставлять одинаковую сложность записи:
например, вес + повторы, а не «новое упражнение» против повтора готового значения.

| Тренер | Тренировка 1 | Тренировка 2 | Тренировка 3 |
| --- | --- | --- | --- |
| T01 | сначала голос, затем касания | сначала касания, затем голос | сначала голос, затем касания |
| T02 | сначала касания, затем голос | сначала голос, затем касания | сначала касания, затем голос |

Переключать способ между блоками заранее, не по удобству результата. Каждый блок
содержит половину подходов. Отдельно проверить «Как в прошлый раз» и пометить такие
попытки: экспорт считает их отдельно, они не заменяют группу ручного ввода.
Во время выполнения упражнения телефон не использовать; запись делается после подхода.

## Наблюдение за попыткой

Записать код тренера/тренировки/попытки, запланированный способ, упражнение и число
подходов во фразе. Наблюдатель отдельно засекает время от намерения записать до
проверки результата: автоматический журнал не видит поиск телефона и обдумывание.
Не помогать без просьбы; помощь и её длительность отметить.

Автоматически (`trainer-prototype:field:v1`):

- голос: начало нажатия, отпускание, исходный текст, разобранные пункты, удаления,
  ошибки распознавания, момент «Записать» и число сохранённых подходов;
- касания: открытие редактора → успешное сохранение;
- быстрый повтор: нажатие → сохранение, отдельная группа.

Вручную для каждого блока:

| Поле | Что записать |
| --- | --- |
| Устройство | модель, ОС, браузер и версия, ввод пальцем/клавиатурой |
| Условия | музыка/тихо, разговоры рядом, примерная дистанция до микрофона |
| Язык | русский, казахский, смесь; фактические слова без персональных сведений |
| Сеть | Wi-Fi/мобильная/нет связи, заметные задержки |
| Настройки | размер текста, спокойный режим, разрешение микрофона |
| Исход | самостоятельно/с помощью/не получилось, ошибка в итоговых данных |
| Обходной путь | переход к тексту, касаниям или привычным заметкам и причина |
| Прерывания | разговор, звонок, отвлечение; длительность по наблюдателю |

Русский язык сейчас задан в распознавании. Казахские и смешанные фразы всё равно
фиксировать как попытки с их реальным исходом, не объявлять поддержанными заранее.
Отказ микрофона и отсутствие сети — результаты, а не повод исключать неудобный блок.

## После каждой тренировки

1. Проверить несколько записей с тренером: записанное соответствует фактическому
   весу, повторам, упражнению и человеку? Сверить все отмеченные ошибки.
2. Выгрузить JSON из профиля. Имя файла: `T01-S01-field.json`; не дописывать имя человека.
   Сохранить рядом ручные наблюдения с тем же кодом, проверить, что JSON открывается.
3. Только после проверки файла очистить полевой журнал для следующей тренировки.
4. Спросить: «Что мешало записывать? В какой момент вы поменяли бы способ?».

## Анализ и решение

Сначала сравнить внутри каждого тренера, затем показать все шесть тренировок.
В JSON `meanMsPerSet` = сумма времени успешных попыток / число записанных подходов.
Незавершённые попытки остаются в событиях: отдельно посчитать их число, ошибки,
повторные попытки и время до окончательного исправления по наблюдениям.
Демо и текст не входят в среднее голоса. Доля фраз без правок считается консервативно:
если попытка содержала удаление, ошибку или ручной ввод, её фразы не считаются чистыми.
Время быстрого повтора нельзя сравнивать с полным вводом как равные задачи.

В итогах: средние и медианы по тренеру/шуму/языку, число подходов, доля отказов,
ошибки сохранённых значений, субъективный выбор тренера и дословные причины.
Гипотеза остаётся открытой при разнонаправленных результатах или недостатке попыток.
Порог выигрыша и допустимую частоту ошибок владелец продукта задаёт до основного
теста; произвольный процент успеха после сбора не назначать.
