  и `refero-refs` (42 референса) с `INDEX.md`.
- **Отдельный монорепо `fitness-eco`:** pnpm + Turborepo, `apps/mobile` (Expo / React Native,
  expo-router, reanimated, zustand, TanStack Query), `apps/api` (NestJS + JWT + zod),
  `packages/db` (Prisma + PostgreSQL), `packages/contracts` (общие zod-схемы). Уже есть роли

**Вывод (редакция 2).** Дизайн-язык gymGO **принят** как основа оформления нашего продукта:
палитра, монохром + семантический цвет, Montserrat + Inter, радиусы 14/22/26/30/9999,
таб-бар с центральным действием, шторки, крупные числа — переносятся дословно
(см. `docs/design-system.md`). Не переносятся **продуктовые** сценарии gymGO:
клуб, турникет, QR-проход, рейтинг и «Искра» (ember оставлен только под серии/маскота,
в первой версии не используется). Монорепо `fitness-eco` остаётся проверенным

Осознанные отступления от референса — только по доступности (tertiary не для
значимых метаданных; семантический цвет текста — через ink-варианты).

## 2. Предложение: платформа и стек

Это **предложение**, а не согласованное решение. Платформа пилота в handoff не утверждена.

**Платформа: адаптивное веб-приложение / PWA, один код на обе роли.**
Причина: тренер работает с телефона, но расписание, клиентская база и редактор шаблонов требуют
широкого экрана (handoff §6, §12). PWA закрывает пилот без установки из стора; нативные
возможности (push, Live Activities, действия на экране блокировки) явно отложены до выбора
платформы и не обещаются.

**Стек:**
| Слой | Выбор | Почему |
|---|---|---|
| Клиент | React Native + Expo (expo-router) + `react-native-web` | один код → iOS, Android, web/PWA. Не переписывать при переходе на native |
| Состояние | Zustand + TanStack Query | есть в `fitness-eco`, подходит под серверные данные |
| API | NestJS, JWT, ролевые guard'ы | авторизация проверяется на сервере, а не скрытием UI |
| Контракты | `@app/contracts` — zod-схемы, общие для API и клиента | один источник типов входа/выхода |
| БД | PostgreSQL + Prisma | транзакции, атомарные списания, IANA-зона |
| Тесты | Jest (бизнес-инварианты), supertest (e2e) | сначала тест инварианта, затем код |

**Модули** (по §9 плана): `identity`, `clients`, `scheduling`, `workouts`, `billing-ledger`,
`progress`, `notifications`, общие UI-компоненты.

**Инварианты, которые задают архитектуру:**
- изоляция данных по тренеру и клиенту на сервере;
- идемпотентное и атомарное списание (повторный клик / конкурентные запросы не удваивают);
- версионирование записи: устаревшее предложение не перезаписывает новое время;
- событие посещения, списание и оплата — не одно поле `status`.

**Дизайн-этап (сейчас):** статический HTML-прототип для утверждения. Продакшн-код не пишем,
пока направление не подтверждено.

## 3. Два визуальных направления

Сравнение композиций — в `docs/archive/design-directions.html` (архив первой итерации; обе
композиции были переведены на токены gymGO). Референсы изучены через Refero
(styles/screens/flows), не по памяти.

### A. «Табло» — прибор и расписание-реестр
- **Референсы:** 19–86 (архитектурный архив: 1px линии, табличное выравнивание, нулевые радиусы,
  никаких теней), shadcn/ui (монохромная «чертёжная» система, чёрный CTA, пилюли-бейджи),
  Cron (точность кабины), N26 (леджер-дисциплина).
- **Иерархия:** время → участник → тип/программа → статус. Время — вертикальный якорь.
- **Плотность:** у тренера реестр строк 44–52px с хэйрлайнами; у клиента — одна крупная карточка
  и две числовые плитки.
- **Типографика:** Montserrat 700–900 (заголовки, крупные числа, трекинг −0.2…−0.6px) +
  Inter (UI); все время/суммы — `tabular-nums`; микро-подписи uppercase .12–.14em.
- **Цвет:** ахроматика; смысл несут только еловый (подтверждено), янтарь (ждёт ответа),
  кирпич (ошибка/отмена). CTA чёрный. Цвет никогда не единственный носитель смысла.
- **Взаимодействия:** касание ≥44px, фокус чёрным кольцом, листы 300мс, `reduced-motion` off.

### B. «Карточки» — воздушная подача
- **Референсы:** mymind (крупная карточка-поверхность, акцент только контуром), Symbolic.ai
  (мягкие радиусы, тихая тень), Delphi/Medium (воздух и крупная типографика).
- **Иерархия:** имя и время крупно, статус — тихая пилюля-контур; один визуальный акцент на экран.
- **Плотность:** воздушнее, строки 56–64px, крупные отступы, больше белого.
- **Типографика:** та же система — Montserrat для заголовков и чисел, Inter для UI.
- **Цвет:** тот же токен-набор gymGO; отличие только в композиции, не в палитре.
- **Взаимодействия:** листы и переходы системы, мягкая тень карточек.

### Выбор
**Система — gymGO Design System** (Revolut-style, light, monochrome-first): canvas `#f6f6f7`,
ink `#050505`, mint/amber/danger только для статусов, ember только маскот/серии,
Montserrat + Inter, радиусы 14/22/26/30, листы 340мс `cubic-bezier(.22,.8,.25,1)`.

**Композиция — A «Табло».** Плотный реестр напрямую отвечает главному требованию: тренер
работает между подходами в насыщенном дне, где критичны плотность, пересечения и однозначные
статусы. Тот же набор токенов переносится на широкий экран недельной сетки.

**Из B взят только приём, не система:** клиентская карточка ближайшего занятия получает больше
воздуха и крупный заголовок. Рабочие экраны тренера остаются плотным реестром.

## 4. Зафиксированные токены — gymGO Design System

Палитра, типографика, радиусы и motion переведены на дизайн-систему gymGO (Revolut-style,
light, monochrome-first). Это замена прежнего самостоятельного набора.

```
Поверхности   canvas #f6f6f7 · surface #ffffff · sunken #eeeef0 · scrim rgba(8,8,10,.42)
Текст         ink #050505 · secondary #5e5f60 · tertiary #9ba1a8
Линии         border #e9e9ec · hairline #f0f0f2
Статусы       mint #10c22b (soft .10, ink #0a8a23) — success/active
              amber #f3b84a (soft .16, ink #8a6410) — warning/ждёт ответа
              danger #c22b10 (soft .08) — ошибка/отмена
Ember         #FFB23D → #FF7A1F → #F0420F + glow rgba(255,120,40,.55) — ТОЛЬКО маскот/серии
Шрифты        UI Inter · Display Montserrat 700–800, трекинг −0.3…−0.6
Радиусы       field 14 · card 22 · card-lg 26 · sheet 30 · pill 9999
Тени          карточка 0 1px 2px rgba(8,8,10,.04)
Компоненты    Btn 56px full-width 700/16.5 (primary ink, soft, outline, mint, danger, ghost)
              Pill со статусной точкой; Card 22; Row: 1px hairline + title 15.5/600 + meta 13/500
Движение      ease cubic-bezier(.2,.7,.2,1); листы cubic-bezier(.22,.8,.25,1) 340мс;
              пульс живой точки 2.4s ease-in-out infinite
Доступность   касание ≥44px, фокус видим, контраст текста ≥4.5:1, цвет + текст/иконка
```

**Важное исключение по доступности (приоритет handoff v2).** Tertiary `#9ba1a8` на белом не
проходит для обычного текста. Поэтому значимые метаданные (время, остаток, пояснения) набраны
secondary `#5e5f60`, а tertiary оставлен только для неинформативного декора и неактивных
элементов. Mint/amber для текста используются в затемнённых вариантах `#0a8a23` / `#8a6410`,
а не в чистом виде на soft-фоне.

В приложении используются только UI-роли системы. Ember-градиент и маскот «Искра» не
подключаются: в объёме первой версии серий нет, поэтому тёплый акцент не задействован.
Btn 56px — для основных CTA; в плотных рабочих списках допускается компактный вариант 44px
(адаптация размера к контексту, как требует handoff; отдельный класс, а не другая система).

## 5. Реестр решений

| Решение | Источник | Роль токена/приёма | Почему |
|---|---|---|---|
| Монохром + 3 смысловых цвета | gymGO Design System + handoff §2–3 | цвет = только статус | насыщенный день читается без шума; цвет не единственный носитель смысла |
| Время как вертикальный якорь | 19–86, Cron, Daylish | табличное выравнивание, tabular-nums | тренер сканирует день по времени, а не по карточкам |
| Строки-реестр вместо карточек | handoff, shadcn | 1px hairline, плотность | 7+ занятий и пересечения не превращаются в «карточную кашу» |
| Montserrat + Inter | gymGO Design System | display 800 vs UI Inter | прямая система продукта: крупные числа/заголовки + нейтральный UI |
| Mint / Amber / Danger | gymGO Design System | status-only, CTA монохромный | статус отделён от действия; ember не используется без серий |
| Дифф-рейл переноса | gymGO + handoff §8 | old→new, автор, чей ответ | клиент отличает действующее время от предложенного |
| Рамка пересечения | Daylish (06add84a) | отдельные строки, свои интервалы | нельзя слить персональные пересечения в одну сессию |
| Переключатель участников | handoff §4,13 | ввод не теряется и не переносится | ключевой критерий приёмки |
| Тихая тень карточек, крупный радиус | gymGO Design System | Card 22 + 0 1px 2px rgba(8,8,10,.04) | поверхности читаются без тяжёлых границ, воздух на клиентских экранах |
| Главный маскот — рысь №7 | Прямой выбор пользователя, 25.09.2026; [решение и точный референс](design-exploration/MASCOT-DECISION.md) | пятнистая рысь с кисточками и Ember-напульсником из листа восьми маскотов | выбран конкретный образ; внедрение в прототип и иконка приложения пока не определены |

## 6. Что собрано в прототипе

Прототип — модульное приложение в `prototype/` (vanilla HTML/CSS/JS, без сборки).
Оболочка: рельса экранов слева, устройство в центре, инспектор правил справа.
Полное описание — `docs/prototype-guide.md`.

**Экраны тренера:** Сегодня, Расписание, Новое занятие, Входящие, Клиенты,
Карточка клиента (Занятия / Программа / Прогресс / Оплаты / Заметки), Проведение
тренировки, Библиотека, Шаблон, Пакеты и оплаты, Приглашение, Профиль, широкий
вариант «Сегодня».

**Экраны клиента:** Главная, Первый вход, Программа, История, Прогресс, Профиль.

**Кликабельные сложные сценарии:**
- **Перенос для обеих ролей:** предложить → ожидание → принять / отклонить / отозвать →
  встречное предложение → устаревшее уведомление открывает актуальное состояние без повтора.
- **Переключение трёх участников** (Алия / Мади / Дана) с разными программами и незавершённым
  вводом: значения хранятся по участнику, не теряются и не перетекают другому.
- **Посещение и списание** — отдельное явное подтверждение, идемпотентно, списание только
  выбранного участника; отмена не списывает автоматически, ручное списание требует причины.
- **Завершение с незаписанными подходами** — «Сохранить записанное и завершить» / «Продолжить
  ввод», без массовой кнопки и без автозаполнения.
- **Пересечения и группы** — общая сессия против независимых пересечений.
- **Ошибка сети** — введённое сохраняется, есть повтор.
- **Состояния** — обычный день / пустой день / загрузка / нет связи; ширины 375 / 390 / 430.

Все данные вымышленные: Данияр, Айгерим, Арман, Алия, Мади, Дана; 60 000 ₸ / 20 000 ₸ / 40 000 ₸.

## 8. Открытые решения (нужны после утверждения)

1. **Платформа пилота:** подтвердить PWA (предложено) или нативные приложения.
2. **Визуальное направление:** система gymGO принята; подтвердить композицию A «Табло»
   (плотный реестр) и точечные заимствования из B.
3. **Название продукта:** placeholder «Кабинет тренера»; gymGO и «Искра» не переносятся.
4. **Авторизация:** предложить реальный механизм; SMS не принимается по умолчанию.
5. **Кто вводит результаты:** в прототипе тренер; требует интервью.
6. **Локальный черновик:** нужен ли в пилоте и какие гарантии даёт; сейчас не обещан.

Дальше: после утверждения — этап 1 (один сквозной сценарий: карточка клиента → одноразовое
приглашение → предложение времени → взаимное подтверждение → сохранение и изоляция данных),
затем шаблоны, группы/переносы, учёт занятий и оплат, прогресс.

### Calendar redesign · September 22, 2026

The schedule retains gymGO canvas #f6f6f7, surface #ffffff, ink #050505, secondary #5e5f60, and semantic amber #f3b84a. Montserrat sets dates and headings; Inter sets appointment rows. A black selected date anchors the white week navigator above a continuous agenda. Time is left-aligned, with client and program to its right. Compact planning rows replace repeated workout buttons. Week navigation crosses months and years. Free windows use the union of occupied intervals; cancelled appointments do not occupy time.

### Clients directory redesign · September 22, 2026

The client directory follows the same monochrome gymGO palette and type system as the calendar. One page title, inline search, and three count filters lead into an alphabetical roster. Each row prioritizes identity, program, next appointment, and a right-aligned remaining-session balance. Neutral initials replace status-colored avatars; amber denotes an actual unpaid amount. No low-balance threshold is inferred. The displayed total reflects the actual roster rather than the unrelated trainer summary fixture.
