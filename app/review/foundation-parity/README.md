# Паритет каркаса: первый проход

29.09.2026, ветка `feat/foundation-parity`. **Паритет не принят.**

## Реализовано

- «Авто» выбирает тему по роли: тренер тёмная, клиент светлая.
- «Авто / Тёмная / Светлая» сохраняется в AsyncStorage. Позднее чтение старого
  значения не заменяет новый выбор, записи выполняются последовательно.
- API `workout` принудительно включает тёмную тему; сам журнал ещё не построен.
- Инструмент `npm run parity` экспортирует web, запускает локальные серверы,
  вызывает эталонный `capture.cjs`, снимает приложение и создаёт HTML-пары.
- Исправлена рамка эталона: 390 × 768 → 390 × 844. Проверка bounding box не даёт
  принять снимок неверного размера. Продуктовые CSS/сценарии не менялись.

## Воспроизведение

Нужен Node 22.18.0, зависимости корня и `app/`, Chromium для Playwright.
Используется уже установленный в корне Playwright, новая browser-зависимость
в приложение не добавляется.

```sh
cd app
npm run parity
SCREENS=t-profile,c-profile npm run parity
```

Результат: [HTML-сравнение](parity/generated/index.html),
[машинный отчёт](parity/generated/index.json).
Каталог `generated/` исключён из Git; снимки можно приложить к PR.
Частичный запуск не перезаписывает полные закоммиченные `spec-*.json`:
переменная `SPEC_DIR` указывает внутрь результата.

Отчёт намеренно не вычисляет «принято» из наличия PNG. Для отсутствующего маршрута
пишется `route-missing`; для ещё не подключённого состояния —
`state-not-implemented`; существующая заглушка — `captured-not-approved`.
Системная тема браузера светлая во всех случаях: это позволяет заметить ошибочную
зависимость автотемы тренера от системной темы.

## Проверено

- `npm run check`: TypeScript, ESLint, Prettier; 14 поведенческих тестов и
  42 проверки контраста (56/56).
- Web: ручной выбор светлой темы сохраняется после настоящей перезагрузки страницы.
- Android API 36, Pixel 9, Expo Go 57.0.9: профиль тренера в авто тёмный;
  выбранная светлая тема восстанавливается после force-stop и запуска Expo Go.
  Локальные снимки: [авто](parity/generated/native/android-trainer-auto-dark.png),
  [после перезапуска](parity/generated/native/android-trainer-light-restored.png).
- Обе роли в auto/light/dark: снимки 780 × 1688, ошибок выполнения нет.
- Полный отчёт: 114 эталонов, 18 снимков приложения, 96 явно отсутствующих
  комбинаций маршрута/состояния. Ни один экран не отмечен принятым.
- Полные канонические `spec-light.json`, `spec-dark.json` и `index.json`
  пересняты исправленным скриптом. Все 114 рамок — 390 × 844;
  CSS-переменные не изменились, наборы классов сохранены (274/334).
- Исходные миграции не менялись; pgTAP 1/1 и db lint проходили в предыдущем проходе A.

## Открыто

- D1–D5, D7: токены, начертания, собственные SVG, пять вкладок и плавающая панель,
  базовые компоненты. Нынешние профили — заглушки, не профиль из прототипа.
- D9: полный чек-лист, нативные пары iOS/Android и одобрение владельца.
  iOS и настоящие телефоны в этом проходе не проверялись.
- Состояния empty/loading/offline ещё не подключены к каждому экрану приложения.
- Предупреждения зависимостей Expo Router и pointerEvents не подавлялись.

Этот проход не закрывает этап 1 и не подтверждает визуальный паритет.
