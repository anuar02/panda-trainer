# SOM-20 — реальные onboarding и карточки клиентов

Дата: 01.10.2026. Канонический экран: `prototype-fresh/js/screens/welcome.js`;
список/карточка используют стили существующих переносов прототипа.

## Реализовано

- Авторизованный новый пользователь проходит пять шагов настройки. Профиль,
  пространство, рабочие предпочтения, 81 упражнение и необязательный первый
  клиент сохраняются атомарно; существующая настройка не перезаписывается.
- `/workspace/clients`: реальные RLS-данные, поиск имени/телефона, фильтр без
  записи, создание непривязанной карточки с повтором по request_id.
- `/workspace/client/[id]`: реальная карточка, программа и записи; чужой ID
  не открывается. Финансы, прогресс, заметки и приглашения не имитируются.
- Демо-маршруты остаются отдельными. Автоматическая тема workspace — тренерская.

## Проверки

- `npm run check`: 363 теста / 51 suite, TypeScript, ESLint, Prettier.
- `npm run export`: iOS, Android, web.
- Изолированная база trainerApp-som18: 333 pgTAP / 10 файлов, db lint без ошибок,
  генерируемые типы совпадают; `onboarding_concurrency.py` проверяет два setup
  запроса и единственные workspace/первого клиента/81 упражнение.
- `verify.cjs`: headless Chrome 390×844, локальный Auth/Mailpit, два уникальных
  вымышленных аккаунта. Setup → список → reload → создание второго клиента →
  поиск имени/телефона → карточка; другой тренер получает пустой список и не
  может открыть чужую карточку. 6 проверок проходят; runtime/console ошибок
  приложения нет. Единственное исключение — точный 404 `/favicon.ico` локального
  Expo preview, не относящийся к native-приложению. Сценарий удаляет только
  собственные fixtures.

Запуск с работающими изолированными Supabase и Expo web:

```sh
node app/review/onboarding/verify.cjs \
  --workdir /path/to/isolated/supabase-workdir \
  --container supabase_db_trainerApp-som18 \
  --origin http://localhost:8087
```

Снимки: `/tmp/screens/welcome-profile.png`, `welcome-hours.png`,
`welcome-done.png`, `client-list.png`, `client-detail.png`. PNG не хранятся в git.
Скрипт не выводит OTP, токены и конфигурацию; использует только loopback-сервисы.

## Открытая приёмка

Паритет и native-приёмка не объявлены завершёнными. Нужны пары эталон/приложение,
состояния offline/loading/error, крупный текст, клавиатура и проверка на телефонах.
Одобрение login layout не распространяется на эти экраны.

Реальные ограничения: имя тренера пустое до ввода; пропуск требует имени;
сообщение «ссылка готова» отсутствует без настоящего приглашения; планирование
и приглашение недоступны, переход после настройки ведёт в реальные карточки.
Баланс/долг показывают неизвестное значение, а не вымышленный ноль.
Эти временные отличия требуют отдельной визуальной приёмки; SOM-20 и SOM-43
остаются открытыми. Production-домен приглашений pending.
