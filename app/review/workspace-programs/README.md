# SOM-24 — назначение личной программы

Дата: 01.10.2026. [ADR 0029](../../../docs/app/decisions/0029-client-program-snapshots.md).

## Реализация

Карточка клиента → Программа → библиотека шаблонов → отдельное назначение
в карточке шаблона → обновлённая программа клиента. Каждое новое назначение
создаёт новую личную копию; старые копии не меняются (решение владельца SOM-55).
Действие назначения отделено от ещё не подключённого создания занятия.

Команда сохраняется до RPC отдельно для аккаунта/workspace/клиента. При потере
ответа и после перезапуска повтор использует тот же request ID и исходную версию.
Неопределённую команду нельзя заменить другой; повреждённые данные не удаляются
молча. Смена аккаунта или уход с экрана до отправки не запускает старый запрос.
После подтверждённого конфликта требуется явно перечитать шаблон;
после ошибки локальной очистки повтор подтверждает уже созданную сервером копию.

## Проверки

- `npm run check`: 442 теста / 60 suites, TypeScript, ESLint, Prettier проходят
  (включая 13 тестов чтения расписания и 7 проверок навигации редактора).
- Экспорт web, Android и iOS проходит с одним worker; артефакты в `/tmp`,
  вне индексируемого дерева проекта.
- 12 transport/storage tests и 12 hook lifecycle tests: сохранение до RPC,
  неизменяемые аргументы, смена аккаунта/unmount, сохранённый повтор, сбой
  очистки, повреждённое хранилище и различие terminal/ambiguous ошибок.
- 15 headless browser checks проходят: назначение, потеря ответа после commit,
  reload и повтор с тем же request ID/ID программы (`replayed: true`), одна
  receipt/копия после повтора, второй шаблон с новым ID, сохранение плана первой
  копии, reload второй программы. Непредвиденных browser errors нет.
- Синтетические пользователи, workspace/клиенты и Mailpit сообщения удалены;
  тестовые серверы и изолированный стек остановлены после проверки.

```sh
node app/review/workspace-programs/verify.cjs \
  --workdir /path/to/isolated/supabase-workdir \
  --container supabase_db_trainerApp-som18 \
  --origin http://localhost:8088
```

Сценарий использует только отдельные синтетические Auth/Mailpit данные.
Проверяет потерю ответа после server commit, reload/replay и второй шаблон
с проверкой неизменности первой копии через SQL; после запуска удаляет свои данные.

## Открыто

Native и визуальная приёмка, редактирование личной копии, выбор старых копий
в интерфейсе, назначение программы будущим занятиям и отдельный клиентский
экран остаются открытыми. Карточка тренера показывает последнюю копию; хранение
прежних программ не означает готовый интерфейс истории.

  loopback Supabase проходит: `expo export --clear --platform web --max-workers 1`.

  из библиотеки клиента и назначаются непосредственно с открывшейся карточки
  сохранённого шаблона. Явных обходных переходов после создания больше нет.
  Проверяются `clientId` в редакторе и сохранённой карточке, потеря ответа после
