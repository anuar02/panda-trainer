# Сквозной UX-проход тренировки · 23 сентября 2026

Экспертная проверка локального прототипа в изолированном Chromium, не исследование
с настоящими тренерами. Сценарии выполняются через интерфейс, без подмены Store.
Desktop 1440×1000 и мобильные viewport 320/375/390/430×844; запасные шрифты.

## Направление правок

Следуем существующей системе, не меняем бренд: фон `#f6f6f7`, поверхность `#ffffff`,
текст/действия `#050505`, вторичный текст `#5e5f60`, успех `#10c22b`, ошибка `#c22b10`.
Montserrat — заголовки, Inter — рабочий интерфейс; настоящие шрифты требуют
следующего визуального прохода. Данные и контекст выровнены влево, подтверждение
действия — в закреплённой нижней области. Главный визуальный акцент — сегодняшний
результат, не декоративная иллюстрация или уведомление поверх данных.

Навык frontend-design применён к обратной связи и текстам состояний: короткие
подписи, совпадение видимого и доступного названия кнопки, отсутствие перекрывающего
контент сообщения об успехе. Новые изображения и анимации для этих исправлений
не нужны. План сверён с назначением: быстро записать результат и вернуться к клиенту.

## Проверенные пути

- Личная: старт → два подхода → исправление первого → последний подход → выход
  без завершения → возврат на прежнюю позицию → частичное завершение → результаты.
- Группа: черновик Алии → запись Даны → возврат к черновику Алии → отменивший Мади
  → сводка всей группы → продолжение ввода → сохранение → частичное завершение.
- Существующие проверки дополнительно покрывают перезагрузку, конфликт вкладок,
  экспорт, валидацию, клавиатурный фокус и reduced-motion.

Число основных действий без набора текста и прокрутки: старт — 1 нажатие;
запись подхода — открыть + подтвердить (2); исправление — открыть + подтвердить (2);
частичное завершение — открыть сводку + подтвердить (2). Эти значения описывают
сценарий, не измеряют скорость работы человека с экранной клавиатурой.

## Наблюдения и исправления

| Наблюдение | Изменение | Проверка |
|---|---|---|
| Toast перекрывал нижние подходы и оставался после переключения с Даны на Алию | Успех записи отображается в строке над нижней кнопкой, с именем и номером подхода; при смене участника сбрасывается | Проверки текста, отсутствия toast и сброса; ошибки хранилища сохранены |
| На 320 px «Есть неподтверждённый черновик» распадалось на несколько строк | Короткое «Черновик»; после завершения — «Черновик не учтён» | Снимок 320, проверка HTML; неподтверждённое не стало фактом |
| Видимая кнопка «Продолжить» имела доступное имя «Записать» | Доступное имя также начинается с «Продолжить» | Unit и браузерная проверка |
| Отменивший участник имел верхний прогресс 0/13 | Прогресс скрыт для неучаствующего; статус, прошлые данные и запрет ввода сохранены | Браузер проверяет отсутствие 0/13 и кнопок ввода |
| Завершение из конца журнала оставляло сводку результата за пределами экрана | Только переход в завершённое состояние возвращает прокрутку к началу и фокус к заголовку | Сначала воспроизведён падением теста на 320; после правки сводка в viewport |

Обычный выход и возврат сохраняют позицию прокрутки. Завершение не меняет
посещение/списание. Формат сохранённого журнала не менялся; строка обратной связи
не сохраняется как результат тренировки.

## Что осталось гипотезой / следующий проход

- Верхняя область группы довольно высокая, третий участник требует горизонтальной
  прокрутки. Нужно оценить плотность с настоящими шрифтами; пока это не основание
  менять порядок участников или убирать контекст клиента.
- Отдельный быстрый переход из сводки к конкретному черновику может сократить
  действия. Не реализован: сначала стоит проверить потребность на реальном сценарии.
- Скорость ввода, системная клавиатура, Safari и плавность на устройстве не измерялись.
- Успешная автоматизация не доказывает удобство для тренеров. Следующий этап —
  настоящие шрифты и визуальная иерархия ключевых экранов, затем проверка на телефоне.
