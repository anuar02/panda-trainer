# Старт и журнал тренировки

Актуальные исправления после ревью: [пункты 1–8](WORKOUT-REVIEW-FIXES.md).
На «Сегодня» возврат в текущий журнал не дублируется; другой журнал назван по клиенту.


Последнее дополнение: [сворачивание и возврат](TRAINING-WINDOW.md). В активном журнале
есть «Свернуть», в остальных тренерских разделах — постоянная полоса возврата.
Возврат из неё сохраняет живой контекст, не перезапуская занятие.

Актуализация 24 сентября: типичный повтор прошлого результата теперь записывается
явной кнопкой прямо в строке; шторка остаётся для отклонений и черновиков. Есть отмена
последнего быстрого подтверждения. [Решения и проверка](QUICK-ENTRY-REVIEW.md).
Описанные ниже исходная палитра и проверки — история; текущие значения и результаты
находятся в дизайн-системе и WORKPLAN. Просмотр плана без старта ещё не реализован.

## Решение

«Начать тренировку» открывает полноценный экран журнала без промежуточного подтверждения. В расписании уже выбраны запись, время и клиент. Повторный вход: «Продолжить тренировку»; после завершения: «Посмотреть результаты». «Свернуть» открывает «Сегодня», оставляя постоянную полосу возврата; занятие не завершается.

```text
Расписание → Журнал выбранной записи
               ├─ участник → упражнение → подтвердить прошлый результат
               │                         └─ изменить → шторка одного подхода
               ├─ свернуть → другие разделы → полоса возврата → то же место
               └─ завершить → проверка всей группы → сохранённый журнал
```

Группа не требует обязательной шторки «Кто пришёл?»: посещение и списание остаются отдельными действиями. Отменившие запись видны, но ввод для них недоступен. Ожидающий ответа участник помечен; запись подхода не подтверждает его посещение. Незаписанное не превращается в ноль.

Шторка оправдана для короткой задачи — ввода одного подхода. В ней остаются имя клиента, упражнение и номер подхода, поля веса/повторов, явное копирование прошлого результата и подтверждение. Черновик полей не считается фактом. Завершение с пробелами показывает сводку по всем участникам, а не только выбранному.

## Визуальный план и проверка до реализации

Сохраняем утверждённый gymGO: фон #f6f6f7, поверхность #ffffff, текст #050505, вторичный #5e5f60, разделитель #e9e9ec, успех #10c22b. Montserrat — заголовки, Inter — ввод и подписи. Левое выравнивание; компактная шапка, полоса участников, журнал, нижнее действие. Радиусы и интервалы — существующие токены.

Акцент этого экрана — различие «прошлый факт / сегодняшняя запись» и постоянный контекст клиента. Убираем декоративные рекорды и фиктивный таймер. Иллюстрации и генеративное видео здесь отвлекают от повторяющейся рабочей задачи; они не нужны при старте. Переход короткий, однократный, отключаемый reduced motion. Повторный рендер при вводе не должен заново проигрывать переход или терять фокус/прокрутку.

## Границы прототипа

Версионированное локальное хранилище браузера, не сервер и не синхронизация с клиентом. Программа копируется при первом открытии журнала. Подтверждённые подходы и отдельные черновики переживают перезагрузку. Ошибка локальной записи видна; завершение при ней блокируется. Завершённый журнал доступен для чтения и не перезаписывается повторным стартом. Посещение и списание автоматически не меняются.

Без программы экран честно объясняет, что запись подходов пока недоступна; редактор произвольной программы — отдельная следующая итерация. Не выдаём переход в библиотеку за работающее назначение.

## Второй проход: узкий экран

Сохраняем палитру и типографику первого прохода. На телефоне убираем рамку макета:
она отнимала ширину и не помогала работе. Шторка состоит из закреплённого контекста,
прокручиваемых полей и нижнего подтверждения. При открытии клавиатуры приоритет —
имя, поле и действие, а не технические переключатели прототипа. Не запрещаем
масштабирование. В desktop-просмотр добавлена ширина 320 px.

В расписании журнал имеет собственные метки «в работе / завершён»; они не означают
посещение или списание. Конфликт вкладок останавливает устаревшую запись и даёт
скачать копию прямо из шторки, без молчаливого объединения. Действие записи при ошибке
подписано «Записать только в этой вкладке». 64 теста логики, обработчиков и HTML-рендера проходят;
браузерный набор содержит 75 проверок Playwright на desktop и четырёх
мобильных ширинах. Системная клавиатура настоящего телефона ещё не проверена.

Сквозной проход: подтверждение записи больше не перекрывает подходы; черновик
получил короткую подпись, отменивший участник — без ложного прогресса. Выход сохраняет
прокрутку, завершение открывает начало результатов. [Подробности](WORKOUT-UX-REVIEW.md).
