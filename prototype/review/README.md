# Обзор для визуальной приёмки

Открыть `index.html` в браузере либо `/review/` на сервере прототипа.
Это отдельная страница со снимками текущего интерфейса; она не меняет данные приложения.

15 состояний × 320/390 px, высота 844 px. У 12 состояний есть «До / После»;
вечерний реестр истории и две пустые страницы показаны только в текущей версии
с явным пояснением. Всего 30 новых + 24 исходных PNG. Переключатель «После» показывает
«Чернильный блокнот», «До» — сохранённые снимки перед этим проходом. Исходные PNG и
manifest прежней версии находятся в `before/`; генератор их не перезаписывает.
Новые снимки получены 24 сентября 2026 после добавления сворачивания тренировки
из изолированных контекстов Chromium. Свежий полный прогон: 90/90 browser за 40,1 с
без retry (desktop и 320/375/390/430).
Сам обзор проверен на 1440/320: все 54 уникальных изображения, размеры, ссылки, переполнение
и JS-ошибки. Также прошли 78/78 unit и обе проверки типов; это не проверка iPhone.

[Сворачивание и возврат](workout-window/index.html): 5 состояний на 320/375 px.
Генератор — `python3 prototype/review/workout-window/build.py`, после полного
успешного browser-прогона в `output/design-review/results`.

[Отдельное сравнение быстрого ввода](quick-entry/index.html) содержит исходный
«Чернильный блокнот» и новую запись одним нажатием на 320/375 px. Его версия «До»
позже исходного дизайна в основном обзоре. [Решения и ограничения](../QUICK-ENTRY-REVIEW.md).

## Обновление

Из корня репозитория, после изменения визуала:

```sh
PLAYWRIGHT_HTML_OUTPUT_DIR=output/design-review/report npm run test:e2e -- --project=mobile-320 --project=mobile-390 --grep 'local typography:|client secondary:|workout UX:|invitation:|sheet:' --output=output/design-review/results
python3 prototype/review/build.py
```

Генератор запускать только после успешного полного прогона этой выборки. Он копирует
PNG без изменений, собирает страницу и manifest с источниками и SHA-256. Для новой
даты/прогона обновить сведения о дате и проверке в `build.py`, этом файле и WORKPLAN.
Сведения о текущей приёмке не должны автоматически переноситься на следующие версии.
`manifest.json` фиксирует исходники интерфейса на момент сборки; снимки не обновляются
сами при изменении приложения. Старый полный отчёт `output/playwright/` не затрагивается.
