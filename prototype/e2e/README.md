# Браузерные проверки прототипа

## Запуск

Нужны Node.js/npm, Python 3 и установленный Chromium Playwright. На новом компьютере:

```sh
npm ci
npx playwright install chromium
```

Основной цикл:

```sh
npm run test:prototype        # 82 unit-теста + 115 браузерных проверок
npm run test:e2e              # только браузер
npm run test:e2e:typecheck    # типы конфигурации и браузерных тестов
npm run test:e2e:report       # открыть локальный HTML-отчёт
```

При работе агента в sandbox для запуска браузера и локального сервера может
потребоваться разрешение. Это не требует разрешений macOS на управление экраном.
Для этой сессии разрешён префикс `npm run test:e2e`.

Быстрый отдельный сценарий и видимый тестовый браузер:

```sh
npm run test:e2e -- --project=mobile-390 -g 'journal:'
npm run test:e2e:headed -- --project=desktop
```

Сервер стартует/останавливается автоматически на `127.0.0.1:4186` и отдаёт только
папку `prototype`, не корень репозитория с `.env.local`. Уже занятый порт вызывает
ошибку: тесты не переиспользуют неизвестный сервер. Не запускайте два набора
одновременно на одном порту; внутри набора используются два параллельных worker.

Каждый тест получает новый браузерный контекст и пустое хранилище. Проверка конфликта
открывает две вкладки с общим хранилищем только внутри своего контекста. Перезагрузка
внутри теста сохраняет только его данные. Личный Chrome, профиль, cookies и журналы
на порту 4175 не используются. Никаких прямых вызовов Store для выполнения сценариев:
действия идут через интерфейс. Код страницы читается только для проверок геометрии
и анимаций. Computer Use для запуска не нужен; компьютер должен оставаться включён.

## Покрытие

Двадцать два сценария выполняются в Chromium на desktop 1440×1000 и мобильных
viewport 320/375/390/430×844:

Новый сценарий `quick entry:` проверяет подтверждение без шторки, отмену, изменение
веса, три подхода, исправление и перезагрузку. Проверяются фокус, цели нажатия от
44 px и отсутствие переполнения. На мобильных дополнительно проверяется высота 667 px;
это не проверка системной клавиатуры iOS. Два сценария `workout dock` проверяют
сворачивание, разделы/вложенный экран/широкий кабинет, возврат к прокрутке и черновику,
перезагрузку, исчезновение после завершения и контекст участника группы.
Три сценария `review fixes:` проверяют шаг от подсказки, отображение черновика,
имя при прокрутке, возврат к другому незавершённому занятию и завершение во второй
вкладке с экспортом местных правок.
Сценарий `workout polish:` проверяет целиком видимый первый подход группы при
высоте 640 px, цели нажатия, запись и контекст при прокрутке/переключении участников.
Следующие пункты описывают прежние 15 сценариев.

1. Прямой старт → пустой ввод → дробный вес → черновик после перезагрузки →
   подтверждение через Enter → частичное завершение → результаты после перезагрузки.
2. Фокус внутри шторки, Shift+Tab/Tab, Escape, возврат к кнопке подхода,
   доступность нижнего действия, отсутствие горизонтального переполнения страницы.
3. Изолированные черновики участников группы, запрет ввода отменившему,
   сводка всех участников при завершении.
4. Создание занятия с явным подтверждением пересечения, программа «позже»,
   сохранение и подтверждение участия клиентом после перезагрузки.
5. Предложение переноса не меняет исходное время до ответа тренера;
   принятое время сохраняется после перезагрузки.
6. `prefers-reduced-motion` не запускает анимацию открытия шторки.
7. Две реальные вкладки: устаревшая не перезаписывает сохранённый подход;
   предупреждение и скачивание доступны внутри шторки, JSON содержит её черновик.
   Завершение при конфликте блокируется; перезагрузка первой вкладки сохраняет её факт.
8. Клиент предлагает перенос → тренер предлагает другое время → перезагрузка →
   клиент принимает. До принятия действует исходное время, после — встречное;
   длительность занятия сохраняется.
9. Личная тренировка: несколько подходов, исправление, выход/возврат с сохранением
   прокрутки, частичное завершение с видимым итогом; успех не перекрывает журнал.
10. Группа: черновик одного участника и факт другого, возврат, отменивший участник,
    общая сводка, продолжение и завершение. Подписи и обратная связь не путают клиентов.
11. Локальные Inter/Montserrat действительно загружены без Google Fonts; время
    отделено от имени, главные экраны не переполняют viewport. Снимки обеих ролей.
    У клиента также проверяются колонки действующего/предложенного времени и пакет.
12. Частая шторка подхода и клавиатурные открытия без WAAPI-анимации; редкая шторка
    240 ms прерывается клавиатурой и сменой reduced-motion. Тестовый наблюдатель
    записывает вызовы `Element.animate`, затем вызывает оригинал без изменения.
13. Приглашение: GPT Image рысь загружена в активном приглашении и состоянии без занятий, CTA видна на
    первом экране, состояния честно показывают ограничения демо. Переход на главную.
14. Программа/история/прогресс/профиль клиента: полные макеты, карточка планки в
    секундах, смена упражнения и таблица, уведомления только этого клиента,
    пустые состояния четырёх разделов, загрузка и offline.
15. Десять справочных экранов тренера: снимки и отсутствие ошибок; открытие карточки
    клиента, общий компонент прогресса, правильный выбранный шаблон, настройки не
    притворяются уведомлениями. Это проверка входа на экраны, не всех их действий.

Необработанное исключение или console.error проваливают тест.
Повторы по умолчанию выключены: не скрываем нестабильность автоматическим retry.

## Артефакты и ограничения

- `output/playwright/report/index.html` — отчёт.
- `output/playwright/results/` — снимки личного и группового пути, шторки и конфликта, скачанные тестовые
  JSON-копии журнала для каждого размера; при сбое также
  screenshot, video.webm, trace.zip и контекст ошибки.
- Артефакты локальные, исключены из Git. Каждый новый прогон заменяет предыдущий
  отчёт/результаты; сохраните нужную трассировку перед повторным запуском.
- Трассировку можно открыть: `npx playwright show-trace <путь-к-trace.zip>`.

Inter/Montserrat включены в `prototype/assets/fonts/` вместе с лицензиями.
Обычные снимки теперь используют настоящие шрифты; `home()` ждёт `document.fonts.ready`.
Внешние Google Fonts блокируются, а отдельный тест требует отсутствия запросов к ним
и статуса `loaded` обеих семей. Режим `E2E_LIVE_FONTS` больше не используется.
Старые снимки до этого прохода были сделаны с запасными шрифтами.

Снимки прикреплены к отчёту, но автоматических pixel-diff эталонов пока нет.
Мобильный viewport — не настоящий iOS/Android: системная клавиатура, Safari,
тактильные ощущения и плавность анимации требуют отдельной проверки на устройстве.
Нет покрытия всех экранов, серверной авторизации и настоящих финансовых операций.

Конфигурация основана на официальной документации:
[configuration](https://playwright.dev/docs/test-configuration),
[web server](https://playwright.dev/docs/test-webserver),
[visual comparisons](https://playwright.dev/docs/test-snapshots).
