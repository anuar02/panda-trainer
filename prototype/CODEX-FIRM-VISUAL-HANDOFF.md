# Handoff для Codex: более строгий визуальный вариант — сравнение

24 сентября 2026. Репозиторий `trainerApp`. Автор задания: Claude (по просьбе пользователя).

## Задание

Сделай **переключаемый вариант оформления «Строгий»** и страницу сравнения
«текущий / строгий» на ключевых экранах. Основной вид прототипа по умолчанию не меняется.
Решение, какой вариант оставить, принимает пользователь после просмотра.
Не коммить, пока пользователь не попросит.

## Почему

Пользователь спросил, не слишком ли интерфейс мягкий или «женственный». Вывод Claude:

- **Основные цвета нейтральные и строгие:** чернила `#111110` и синий `#2b48d6` оставляем.
- **Мягкость создают четыре вещи вместе:**
  1. тёплая бежевая гамма повсюду — `--canvas #f4f2ed`, `--sunken #ece9e2` на вторичных
     кнопках (например «Завершить тренировку»), `--border #e3dfd6` и коричневые тени
     `rgba(40, 32, 20, …)`;
  2. большие скругления: карточки 22–26 px, шторки 30 px, много «таблеток»;
  3. пастельные заливки статусов: `--mint-soft`, `--amber-soft`, `--accent-soft`
     на строке следующего подхода;
  4. два акцента на одном тихом элементе (синяя подпись и синий шеврон в полосе тренировки).

Цель — рабочий инструмент без потери «Чернильного блокнота»: бумага остаётся слегка тёплой,
типографика и синий не меняются. К холодному серому `#f6f6f7` прежнего gymGO не возвращаемся.

## Что сделать

### 1. Сначала токенизировать скругления (без визуальных изменений)

В `css/components.css` около 30 жёстко заданных `border-radius` (12, 14, 16, 18, 20, 10, 9,
13, 6 px) при 84 объявлениях всего. Без этого шага вариант не переключится одним набором
токенов.

- Сопоставь каждое жёсткое значение с ролью: поле, кнопка, чип, карточка, вложенная карточка,
  строка, миниатюра. Добавь недостающие токены радиусов в `tokens.css`, с комментарием.
  Правило из шапки `tokens.css`: сначала описать решение в `docs/design-system.md`,
  потом добавить токен.
- **Этот шаг не должен менять ни пикселя.** Сверь снимки до и после (320 и 375,
  «Сегодня», журнал, шторка подхода); расхождения — дефект шага.

### 2. Набор токенов «Строгий»

Отдельный файл `css/tokens-firm.css`: переопределения под `:root[data-visual="firm"]`.
Включение — параметром `?visual=firm`, по образцу существующего `?now=`. Параметр должен
сохраняться при навигации внутри прототипа. В демо-панели широкого режима — переключатель
рядом с «Обычный день / Пустой день…».

Стартовые значения — гипотеза, их можно подправить по снимкам, с объяснением в отчёте:

| Токен / место | Сейчас | Строгий |
|---|---|---|
| `--canvas` | `#f4f2ed` | ~`#f3f3f1` (почти нейтральная, едва тёплая бумага) |
| `--sunken` | `#ece9e2` | ~`#ededeb` |
| `--border` / `--hair` | `#e3dfd6` / `#efece5` | ~`#e2e2df` / `#ececea` |
| Тени | `rgba(40, 32, 20, …)` | нейтральные `rgba(17, 17, 16, …)`, прозрачность та же |
| `--r-card` / `--r-card-lg` | 22 / 26 | 14 / 16 |
| `--r-sheet` | 30 | 20 |
| Кнопки | таблетка / 14 | 12 (главные и вторичные) |
| Чипы-фильтры | таблетка | оставить таблеткой (единственное место) |
| Вторичная кнопка (`soft`) | бежевая заливка | белая `--surface` с рамкой `--border` |
| Метки статусов | пастельная заливка-таблетка | точка цвета статуса плюс текст, без заливки |
| Следующий подход в журнале | `--accent-soft` плюс синяя черта | только синяя черта |
| Полоса «Вернуться к тренировке» | синяя подпись и синий шеврон | один акцент: подпись графитом `--sec`, шеврон синий (или наоборот, выбрать по снимку) |

Не менять: `--ink`, `--accent`, семантические `--mint`, `--amber`, `--danger` (только их
использование в метках), шрифты, размеры текста, отступы, иконки, иллюстрации,
компоновку экранов.

### 3. Страница сравнения

`review/visual-firmness/index.html` по образцу `review/workout-window/`: `build.py`,
`manifest.json` с источником и SHA-256 каждого PNG. Снимки через интерфейс в Chromium
(Playwright), чистые демоданные, реальные шрифты.

Пары «текущий | строгий», ширины **375** и **320**:

1. «Сегодня» (`?now=08:00`) — карточка следующей тренировки, статусы.
2. Журнал личной тренировки после двух записанных подходов.
3. Шторка записи подхода.
4. «Сегодня» со свёрнутой тренировкой (полоса возврата).
5. Карточка клиента (пакет, «К оплате», статусы занятий).
6. Журнал мини-группы (`?now=20:30`) с полосой участников.

Под каждой парой — одна строка о том, что изменилось. Без оценок «лучше».

## Проверки

- `npm run test:unit`, `npm run test:e2e`, `npm run typecheck`, `npm run test:e2e:typecheck`,
  `git diff --check`.
- Без `?visual=firm` снимки совпадают с текущими (шаг 1 и отсутствие утечек варианта).
- Контраст в строгом варианте: текст `--sec` на новом `--canvas` и на `--sunken` — не ниже
  4,5:1; рамка вторичной кнопки различима на `--canvas`. Цифры приведи в отчёте.
- Проверь, что метки статусов без заливки не потеряли различимость: «Подтверждено»,
  «Ждёт ответа», «Журнал в работе», «К оплате», «Не участвует».
- `graft build` после изменений.
