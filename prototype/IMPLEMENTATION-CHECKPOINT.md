## Реализовано

- Вторичные экраны клиента: полные упражнения, компактные пустые состояния,
  разделение посещений и операций, актуальный пакет в профиле. График прогресса
  с реальными датами/значениями и нулевой базой, доступная таблица; одна запись
  без тренда. Общий компонент используется также тренером.
- Детали упражнения учитывают программу и секунды; устранён сбой `KV`.
  Уведомления клиента не показывают события других демоклиентов.
- Справочные экраны тренера: даты/статусы не сжимают друг друга, длинные названия
  переносятся; исправлен `client.open`, библиотека показывает выбранный шаблон.
  Недоступные настройки/редактор/дублирование больше не выдают чужой экран или успех.
  [Полный обзор и ограничения](SECONDARY-SCREENS-REVIEW.md).
- Главная клиента: время крупнее даты, программа отдельной строкой; сравнение двух
  времён переноса вместо сплошного цветного предупреждения. Компактный пакет,
  программы будущих занятий переносятся, не обрезаются повторяющимися метаданными.
- Приглашение и отсутствие первого занятия используют две существующие GPT Image
  иллюстрации. Реальная авторизация/доставка не обещаются; переключатель демосостояний
  отделён от карточки. Видео Seedance не интегрировано.
- Повторный ввод подходов и клавиатурное открытие без входного движения. Редкая
  шторка от нажатия — 240 ms, cubic-bezier(.32,.72,0,1); ввод/клавиатура/reduced-motion
  прерывают движение. Закрытие мгновенное. Пульсация ожидания человека удалена.
- [Передача визуальной основы](NATIVE-DESIGN-HANDOFF.md): переносим UX/состояния/токены,
  не браузерные обходные механизмы. Выбор Swift/RN и библиотек ещё не сделан.
- Локальные Inter/Montserrat с лицензиями и происхождением в `assets/fonts/`.
  Главная: колонка времени 72 px без столкновения с именем. Группа: три участника
  видны без горизонтальной прокрутки, программа в активном контексте, ожидание ответа
  остаётся явным. Личная полоса прогресса больше не схлопывается во flex-контейнере.
- Прямой старт в журнал; шторка отдельного подхода; контекст клиента и времени.
- Успех записи — строка с именем и номером подхода над нижним действием, без
  перекрытия результатов. Сбрасывается при смене участника, не сохраняется в журнал.
  Короткие подписи черновиков согласованы с доступным именем кнопки. Отменивший
  участник не получает прогресс и подпись «Записываем». Завершение возвращает к
  началу результатов и фокусирует заголовок; обычный возврат сохраняет прокрутку.
- Подтверждённые факты отдельно от черновиков; дробный вес с запятой/точкой,
  целые повторы/секунды, явное копирование прошлого результата.
- Локальные журналы по записи, участнику, упражнению и подходу; сохранение после
  перезагрузки, копия программы и времени старта, завершённые результаты для чтения.
- Проверка всей группы; отменившие не получают неявных результатов/посещений.
- Ошибки хранилища и конфликт устаревшей вкладки не маскируются успехом;
  объяснение и скачивание копии доступны прямо в шторке ввода. При ошибке действие
  подписано «Записать только в этой вкладке». Импорт/слияние ещё не реализованы.
- Мобильная компоновка без декоративной рамки, ширина 320 в просмотрщике,
  VisualViewport без перерисовки ввода; шторка с прокруткой полей и закреплёнными
  контекстом/действием. Pinch zoom доступен.
- Перенос выбранного занятия, неизменное исходное время до ответа, встречные
  предложения обеих сторон, защита от повторного/неправомерного ответа в демо.
- Главная клиента показывает ближайшее занятие, поздние запросы — отдельно;
  отменённое и завершённое не выдаются за предстоящее.
- Посещение не отмечается от открытия шторки. Списание отдельно, один раз,
  из пакета соответствующего клиента. Календарь и история различают факты и записи.
- Создание занятия действительно добавляет запись, проверяет будущее время,
  длительность, клиентов, программу и явное согласие с пересечением.
  Новая запись ждёт согласия клиента; программа «позже» остаётся отсутствующей.
- Расписание, отмены, ответы участников и история переносов сохраняются локально
  в `trainer-prototype:appointments:v1`. Запись выполняется до изменения памяти;
  ошибка квоты, повреждённые данные и устаревшая вкладка не дают ложного успеха.

## Проверено

```sh
node --test prototype/tests/actions.test.cjs prototype/tests/journal.test.cjs prototype/tests/reschedule.test.cjs
npm run test:e2e
npm run test:e2e:typecheck
npm run typecheck
git diff --check
```

64 теста проходят. Тесты обработчиков выполняют исходный диспетчер действий
с небольшими подменами событий, не настоящий браузер. Проверены HTML-рендеры всех
зарегистрированных экранов в четырёх демосостояниях. TypeScript-проверка относится
к вспомогательному проекту, а не к vanilla-JS интерфейсу.

Computer Use оставался нестабилен после «готово». По согласованию с пользователем
основная проверка переведена на Playwright. Текущий набор — 75 браузерных проверок:
пятнадцать сценариев × desktop и 320/375/390/430. Финально 75/75 за 34,6 с без retry,
64/64 unit, обе проверки типов и diff-check. Открытие десяти справочных экранов
не заменяет покрытие всех действий внутри них.
Предыдущий проход конфликта вкладок и встречного переноса — 40/40 за 28,5 секунды.
Предыдущий набор из шести сценариев
также прошёл повторный прогон: 60/60 за 44,6 секунды без retry. Подтверждены прямой
старт, ввод, черновики/результаты после перезагрузки, группа, фокус, создание,
подтверждение участия, перенос и reduced-motion. Снимки шторки 320 и desktop
осмотрены. Отчёт, снимки, видео и трассировки доступны без управления личным Chrome.
Пользовательские локальные журналы не удалялись.

Дополнительный проход: реальный конфликт двух вкладок воспроизведён, проверены
скачивание JSON с черновиком и сохранность факта первой вкладки после перезагрузки.
Предупреждение и экспорт перенесены в доступную область шторки, снимок 320 осмотрен.
Встречный перенос также проверен: клиент предлагает → тренер меняет время →
перезагрузка → клиент принимает; исходное время действует до согласия.

Сквозной UX-проход добавил несколько подходов, исправление, выход/возврат с проверкой
позиции прокрутки, частичное завершение из конца журнала и видимость итогов; для группы
— черновик и факт разных участников, продолжение из общей сводки и завершение.
Переход к результатам сначала воспроизведён падающим тестом, затем исправлен.
Снимки desktop и всех четырёх мобильных ширин выборочно осмотрены.
[Наблюдения, решения и границы](WORKOUT-UX-REVIEW.md).

Ограничения: системная клавиатура телефона и плавность
обычных анимаций ещё не приняты. Тестовый прогон теперь использует локальные

Снимки ключевого пути осмотрены с настоящими шрифтами; pixel-diff эталоны не заведены.
[Визуальный проход](VISUAL-REVIEW.md). Подробности:

## Границы и следующий проход

1. Вторичные экраны и экспертный проход согласованности завершены; следующий рубеж —
   визуальная приёмка направления пользователем. Бренд и весь интерфейс не объявлены
   утверждёнными. Проверки — страховка изменений, не отдельный основной продукт.
   Физический iPhone/Safari сейчас не блокирует работу; нативные механики проверяем
   в выбранном стеке позже, согласно уточнению пользователя.
2. При будущих изменениях сценариев расширить покрытие отмен и отклонения/отзыва;
   принятый обычный и встречный перенос уже проверены после перезагрузки.
3. Создание реализовано локально. Редактор программы после создания и перенос
   мини-группы ещё не реализованы. Реальные уведомления/доставка отсутствуют.
4. Журналы и расписание постоянны только в этом браузере. Посещения, списания,
   оплаты и изменения балансов пока в памяти демосеанса. Новые карточки клиентов
   попадают в сохранённый снимок при успешном изменении расписания, не сами по себе.
   Серверной синхронизации нет. Слияние одновременных вкладок не реализовано;
   сравнение версии защищает от обнаруженного устаревшего снимка, не заменяет
   транзакции сервера. Не использовать прототип для реального учёта.
5. Не выдавать клиентские проверки ролей за серверную защиту. Не добавлять
   изображения/генеративное видео в рабочий журнал: этому экрану они не помогают.
6. Поиск/фильтры библиотеки и сохранение редактора пока недоступны. Прогресс читает
   демонстрационную историю, не новые журналы; приглашение тренера — сценарий Тимура.

Визуальная основа gymGO сохранена: Inter/Montserrat, светлый фон, чёрные действия,
семантический цвет. Имя/бренд не переутверждались. Добавлена dev-зависимость
`@playwright/test` и скачан отдельный Chromium в стандартный кэш Playwright.
Глобальные настройки и реальные внешние записи в этом проходе не менялись.
