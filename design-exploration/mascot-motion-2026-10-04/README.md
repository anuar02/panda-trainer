## Воспроизводимость

Из этой папки, без root и без генеративных API:

```sh
python3 -m pip install --user pillow==12.3.0 imageio-ffmpeg==0.6.0 numpy==2.4.6
python3 build_candidates.py
```

Если в окружении нет pip, установите его локально стандартным `get-pip.py`
с `--user`; системный Python не меняется. Версии и параметры текущего прогона
сохранены в отчёте. Исходные mp4 и готовые `out/` не перезаписываются.
Кадры извлекаются во временную папку вне git; итоговые последовательности
хранятся в спрайт-листах. Чтобы получить отдельный PNG, извлеките прямоугольник
кадра из `sprite.webp` по координатам `sprite.json`; временные кадры конвейер
автоматически удаляет. Пересборка одной позы: `python3 build_candidates.py --pose wave`.
Хромакей `#00B140`, similarity 0.13, blend 0.06, green despill mix 0.6 expand 0.1,
три erosion и blur 0.8 — из одобренного `key_video.sh`. Общая область альфы
всех кадров обрезает пустые поля без покадрового изменения масштаба.
После resize альфа ≤8 обнуляется, ≥247 становится 255; промежуточная
альфа округляется к 16 уровням (шаг 17), RGB прозрачных пикселей обнуляется.
Это снижает шум альфы без дополнительной эрозии. Итоговая ширина 320 px, шаг 12 fps.
WebP пробует quality 80/70/60 и сохраняет 60 при превышении бюджета;
атлас использует lossy RGB quality 80 с сохранением альфы. Нижние значения
качества не оставлены: целевой вес не оправдывает размытие деталей персонажа. Все данные о кадрах/размерах/петлях —
[manifest.json](manifest.json), прямое локальное открытие использует manifest.js.

В `candidates/<pose>/`:

- `animation.webp` — формат (а), анимированный WebP с альфой;
- `sprite.webp` + `sprite.json` — формат (б), атлас RGBA с координатами кадров;
- `poster.png` — статичный первый кадр для reduce motion;
- `contact.webp` — раскадровка, `seam.webp` — первый/последний рядом.

Размер на диске и память после декодирования — разные величины. JSON содержит
размер атласа; его базовый расход RGBA равен width × height × 4 байт.
Это нижняя оценка, без накладных расходов декодера/GPU и копий.

## Рекомендация для выбора

Для коротких автономных моментов рекомендую начать оценку с **(а) WebP**:
один файл и существующий expo-image по условиям брифа, без отдельного таймера
и покадрового переключения React. Он сохраняет те же 12 fps, что и атлас.
Возможность остановить на конкретном кадре/прервать с продолжением здесь
не доказана: страница при паузе показывает постер и при продолжении начинает
заново. Нативные декодеры и память на устройствах в этом пакете не измерены.

**(б) атлас** полезен, когда важны точный кадр, прерывание и синхронизация:
Reanimated может менять координаты окна без React-render каждого кадра.
Цена — удержание всего декодированного атласа и отдельный проигрыватель;
он в этой задаче не создаётся. Вес и расчёт RGBA для каждой позы смотрите в
отчёте. Оба формата имеют одинаковое исходное движение; формат сам по себе
не увеличивает плавность. Для calm / системного reduce motion в будущем
нужен статичный PNG, без запуска декодирования анимации и таймера.
Страница уже заменяет WebP постером и выключает CSS для обоих вариантов
reduce motion. Решение по приложению и ADR 0005 этим сравнением не меняются.
