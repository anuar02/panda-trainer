# Кабинет тренера — прототип

Кликабельный прототип двустороннего приложения **тренер ↔ клиент**: расписание,
согласование переносов, проведение тренировки с записью результатов, программы,
пакеты и оплаты.

Это **дизайн-этап**. Продакшн-кода приложения здесь нет: только прототип
интерфейса, дизайн-система и документация. Реальный стек, бэкенд и авторизация
не выбраны (см. «Открытые решения»).

## Быстрый старт

Откройте прототип в браузере — зависимостей и сборки нет:

```bash
open prototype/index.html          # macOS
# или
python3 -m http.server 8000        # затем http://localhost:8000/prototype/
```

Внутри: переключатель роли **Тренер / Клиент**, состояния
**Обычный день / Пустой день / Загрузка / Нет связи**, ширины **375 / 390 / 430**
и широкий вариант «Сегодня». Справа — правила экрана и счётчики проверки сценариев.

## Документы и приоритет

1. `trainer-design-handoff-v2.md` — **приоритетный** источник требований.
2. `docs/design-system.md` — токены и компоненты (как перенесены из gymGO).
3. `docs/prototype-guide.md` — что и как проверять в прототипе.
4. `DESIGN.md` — журнал решений и открытых вопросов.

При расхождении требований сверяйтесь с handoff v2 и `DESIGN.md`.

## Источник дизайна

Дизайн-язык перенесён из референса **gymGO**. Референс лежит локально в
`gymGO (2)/` и **не коммитится** (это ~42 МБ сгенерированных артефактов).
Точка правды по токенам — `gymGO (2)/src/src_ui.jsx` (объект `T`) и
`gymGO (2)/Design System.md`. Значения уже перенесены в
`prototype/css/tokens.css`; соответствие и осознанные отступления описаны в
`docs/design-system.md`, поэтому для работы референс не обязателен.

Референс — это **образец вкуса и хореографии, а не продакшн-код**. Его продуктовая
логика (клуб, турникет, сканы, рейтинг) не переносится.

## Что уже сделано

- Дизайн-система перенесена: цвет, типографика (Montserrat + Inter), радиусы,
  тени, моушн, компоненты (кнопки, пилюли, карточки, строки, шторки, таб-бар с
  центральным действием, кольцо, большие числовые поля).
- Экраны тренера: Сегодня, Расписание, Новое занятие, Входящие, Клиенты,
  Карточка клиента, Проведение тренировки, Библиотека, Шаблон, Пакеты и оплаты,
  Приглашение, Профиль + широкий вариант «Сегодня».
- Экраны клиента: Главная, Первый вход, Программа, История, Прогресс, Профиль.
- Сложные сценарии: перенос (предложение → ожидание → принятие/отказ/отзыв →
  встречное → устаревшее), проведение с переключением участников, посещение и
  идемпотентное списание, завершение с незаписанными подходами, пустое/загрузка/
  нет связи.
- Скриншоты в `screenshots/`.

## Что дальше

1. Утвердить визуальное направление и токены.
2. Решить открытые вопросы из `DESIGN.md` (авторизация, платформа, кто вводит
   результаты).
3. UI/UX-правки прототипа → затем реализация сквозного сценария.
