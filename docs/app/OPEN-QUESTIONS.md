## SOM-39: отдельная круглая «+» и fallback dock

05.10.2026, бриф 21: NativeTabs SDK 57 требует настоящий маршрут для роли search;
отменить tabPress нельзя. До решения владельца действует прямо разрешённый fallback:
пять вкладок и существующая «+» в шапке Сегодня. Отдельный action не реализован.
На iOS 26 dock использует BottomAccessory; на платформах без этого API сохранён
в обычном layout под панелью. Это размещение требует визуального одобрения.
Технический пункт регистрации списка закрыт разрешённым scope исправления #89:
основные вертикальные списки всех десяти вкладок используют публичный marker
на iOS внутри NativeTabs и automatic inset; measured system bottom-padding
Сегодня удалён. Отдельного продуктового решения для этого исправления не нужно.
Server Today вне NativeTabs не получает marker или принудительные insets.
Остаются проверки устройства: сворачивание/возврат, insets последней строки,
состояния/unmount, активный dock и приёмка. Gamma включается установленным
expo-router plugin при prebuild; старый native-клиент может требовать пересборки.
[ADR 0113](decisions/0113-native-system-tabs.md),
[новый отчёт](../../app/review/01-som-39-native-liquid-glass-tabs-fix/README.md).
Исторические ограничения #89: [отчёт брифа 21](../../app/review/21-som-39-native-liquid-glass-tabs/README.md).

## SOM-32: выборочное обновление личной программы

04.10.2026 — закрыто владельцем: после тренировки тренеру предлагается «Обновить
программу»; выбранные упражнения переносятся в **новую** копию личной программы,
старая остаётся. Без подтверждения программа не меняется.
[ADR 0100](decisions/0100-post-workout-program-update-by-trainer.md).

### SOM-32: какие значения обычного упражнения переносить

04.10.2026 — ADR 0100 разрешает выбор веса/повторов/времени, а
`prototype-fresh/js/store.js:1024–1078` предлагает только add/replace/skip/extra sets
и записывает последний сохранённый подход в `prev` для добавления/замены.
В SQL нет поля prev у личной программы. Бриф SOM-32 требует план/факт и перенос
значений выбранных упражнений. До сверки владельцем безопасный вариант:
отдельный снятый по умолчанию пункт «перенести сохранённые значения», последний
валидный сохранённый подход в planned weight/reps/seconds; число подходов отдельно,
частичное завершение не уменьшает план. Добавление/замена без валидного результата
не предлагаются; создание пустой программы отклоняется существующими ограничениями.
Это не считается одобренным новым правилом или принятым экраном.

Дополнительно: SOM-31 использует снимок шаблона занятия, а не ссылку на личную копию.
При невозможности доказать совпадение текущей личной программы с этим снимком
обновление отклоняется как конфликт. Автоматически менять план будущих занятий,
назначение или журнал этой задачей не разрешено. Контракт и проверки —
[ADR 0102](decisions/0102-program-update-receipts-and-sources.md).

## SOM-41: удаление аккаунта общего клиента и двойной роли

04.10.2026 — закрыто владельцем: удаление аккаунта клиента удаляет вход и данные
аккаунта, а карточки у всех тренеров остаются «без приложения» с историей занятий
и оплат; данные других тренеров не затрагиваются. Двойная роль — удаление своего
пространства тренера плюс отвязка клиентских карточек. Юридическая проверка до
реальных данных остаётся отдельным gate.
[ADR 0101](decisions/0101-account-deletion-keeps-trainer-history.md).

## SOM-34: переплата по пакету

03.10.2026 — закрыто владельцем: платёж ограничен текущим долгом выбранного
пакета; переплата отклоняется с ошибкой под полем суммы. Частичная оплата уменьшает
долг, но не посещения. Отрицательный долг и скрытый кредит не создаются.
Реализация и проверки продолжаются; [ADR 0059](decisions/0059-package-creation-and-capped-payments.md).

## SOM-33: создание покупки в приложении

03.10.2026 — prototype-fresh содержит карточки покупки во вкладке «Оплаты»,
но не содержит форму создания. Владельцу предложено действие «Добавить пакет»
в этой вкладке и sheet с названием, числом занятий, общей ценой KZT и необязательной
датой окончания. Владелец одобрил эту форму 03.10.2026 как известное отличие
от прототипа, с layout существующей payment sheet. Внешний вид требует отдельной
приёмки; функциональное решение закрыто. [ADR 0059](decisions/0059-package-creation-and-capped-payments.md).
В вопросе владельцу вкладка ошибочно названа «Пакеты»; каноническое название —
«Оплаты». Чтение существующих пакетов и per-package balances выполняется независимо.
Общий остаток в шапке решён владельцем 03.10.2026: занятия — сумма по неистёкшим
пакетам, долг — сумма по всем пакетам, включая истёкшие (ADR 0059).

## SOM-39, бриф 15: существующий demo/hold голоса

04.10.2026 — в базе после PR #77 (`65e5a5a`) нет существующего voice demo/hold:
`features/workout/workout-screen.tsx` сохраняет disabled-кнопку «Голос», а
workout-demo/runtime хранит только focus/rest. Бриф разрешает движение уже
существующего demo/hold, без нового сценария и без обхода SOM-54. Безопасное
временное правило: реализовать presentation adapters holdIn/holdOut/bubble,
micRing/micHint/bar/vitemIn с synthetic-проверками, сохранить disabled и не
добавлять распознавание, запись или новый flow. Runtime-подключение откладывается
до разрешённого demo/hold в SOM-54; его приёмка не подтверждена этим пакетом.
[Отчёт](../../app/review/15-som-39-motion-workout-r2/README.md).

## SOM-39: функциональная обратная связь записи подхода

03.10.2026 — default prototype app.js добавляет `is-set-recorded`, но его
CSS-анимация определена только в instrument.css: opacity .4 → 1 за 200 ms.
Временно перенесена эта короткая обратная связь с общей default-кривой

анимации не зависит. [ADR 0063](decisions/0063-calm-mode-and-accessible-motion.md).

## SOM-37: тексты расширенной server-ленты

04.10.2026 — prototype-fresh `js/sheets.js:161–187` содержит демонстрационные
строки, клиентские открытые запросы и устаревший trainer subtitle «push отложен».
ADR 0065 уже включает push в v1 отдельной SOM-73. В SOM-37 сохранён subtitle
эталона; production-лента показывает также завершённые события, finished results,
явную отметку прочитанного и bounded pagination по критериям задачи. До решения
владельца используются нейтральные названия kinds без придуманного финансового
результата или текста заметки. Новый текст subtitle и визуальное размещение
счётчика/read/more требуют одобрения владельца; это не разрешённое отклонение
и не приёмка экрана. Прототип не изменён.

## SOM-73: утренняя сводка и проверка native push

04.10.2026 — ADR 0065 задаёт утро в timezone workspace, но не точное время.
04.10.2026 — владелец выбрал **07:00** по часовому поясу workspace:
`PUSH_MORNING_LOCAL_TIME=07:00`, без пользовательской настройки в v1.
Сводка — «План занятий на сегодня» и фактическое число подтверждённых занятий
на активных карточках в своём workspace на момент claim, с открытием текущего расписания. После позднего запуска сводка доступна за текущий
непустой день; прошлые дни не восстанавливаются. Напоминание после начала
занятия пропускается. Тексты новых kinds, subtitle по ADR 0065 и маршрут честного
unavailable/error требуют проверки владельцем вместе с native/parity.
[Контракт и ограничения](PUSH-V1.md), [ADR 0099](decisions/0099-push-device-leases-and-due-evaluation.md).


## SOM-38: контекст PNG-маскота в спокойном интерфейсе

04.10.2026 — `prototype-fresh/js/mascot.js:22–23` сохраняет панду только для
`empty` и `onboarding`, без движения. Текущие вызовы приложения не передают
контекст. `Mascot.context` теперь явно поддерживает эти исключения; неизвестный
контекст временно сохраняет прежнее скрытие, чтобы не раскрывать панду в hero/inline.
Нужна подтверждённая карта существующих вставок по контекстам эталона; автоматическое
назначение `empty` по позе или размеру не применяется. Экраны этой задачей не изменены.
