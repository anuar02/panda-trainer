# 0023. Пересчёт текста при изменении Dynamic Type

- **Статус:** Принято
- **Дата:** 01.10.2026
- **Задача:** SOM-50; общий Text также относится к SOM-17

## Контекст

На iPhone 16e / iOS 26.2 переключение `content_size` с `large` на
`accessibility-large` при открытом picker увеличивало глифы, но сохраняло прежние
высоты текста: заголовок, подсказка, строки и Done обрезались. Холодный запуск с
тем же крупным размером показывал правильные переносы. Это наблюдаемый сбой
живого пересчёта; точная внутренняя причина в native runtime не установлена.

## Решение

Общий `Text` читает `fontScale` из `useWindowDimensions` и использует его как
ключ вложенного `NativeText`. Изменение системного масштаба создаёт новый
native-текстовый узел и запускает измерение. При неизменном масштабе узел
сохраняется. Размеры, lineHeight, классы и accessibility props передаются как
раньше; масштабирование не отключается и не ограничивается. TextInput не меняется.

## Последствия и проверка

Изменение применяется ко всем потребителям общего Text, включая Button и Sheet.
При смене масштаба возможен сброс выделения текста или фокуса на заменяемом
текстовом узле; бизнес-состояние родителя и значения полей не сбрасываются.
Нормальный размер эталона не изменяется. Исправление проверено живым переходом
large → accessibility-large без перезапуска; до/после и keyboard smoke находятся
в [отчёте](../../../app/review/template-picker/README.md).

Регрессионный тест проверяет сохранение экземпляра при обычном обновлении и
замену при изменении fontScale. Только native-проверка подтверждает отсутствие
обрезания: unit-тест не моделирует измерение iOS. Полная приёмка всех экранов,
максимального размера, compact/landscape и экранных дикторов остаётся отдельной.
