# 0107. Дата и время занятия — отдельные шаги

- Статус: принятое решение владельца; визуальная приёмка открыта
- Дата: 05.10.2026
- Задача: SOM-26, бриф 18

## Контекст

Владелец явно изменил сценарий создания: после выбора клиентов сначала дата,
затем время. Это исключение из ADR 0007, а не новый дизайн редактора.
Эталон остальных элементов — `prototype-fresh/index.html` без параметров,
`js/screens/trainer.js:612–670`; размеры чипов и строк —
`review/parity/spec-dark.json`, классы `chip` и `row`.

## Решение

Порядок: Клиенты → Дата → Время → Программа. Дата выбирается существующими
ChoiceRow; переход выполняется кнопкой «Продолжить», как на остальных шагах
редактора. Автоматического перехода при выборе строки нет. Предыдущий чип
открывает именно указанный шаг, без изменения выбранных полей.

На шаге времени выбранная дата показана той же строкой с подписью «Изменить
дату» из ru-ресурса. Нажатие возвращает к дате. Начало и длительность сохраняют
существующие чипы, тексты, размеры и порядок.

При фактической смене даты начало сохраняется, если оно доступно. При известном
пересечении или недоступном времени начало очищается; «Продолжить» на шаге
времени блокируется до явного выбора. Никакое другое время автоматически не
назначается. Workspace проверяет будущий момент через существующее разрешение
локального времени в часовом поясе workspace; неоднозначное/несуществующее
время также требует нового выбора. Пересечения проверяются существующим
getCollisions, включая актуальное предупреждение сервера. Сервер по-прежнему
окончательно проверяет пересечения и время при отправке.

Проверка относится к смене даты: восстановленный pending-запрос не исправляется
автоматически и сохраняет исходные параметры и подтверждение пересечения для
безопасного повтора. Изменение даты/начала/длительности сбрасывает подтверждение
пересечения по существующему patchSessionDraft. Схема хранения и отправка не
изменены.

SOM-27 использует отдельный RescheduleSheet с полями, без CreateSessionScreen и
без его шагов; перенос не меняется по границам брифа.

## Последствия и проверки

Нет новых библиотек или анимированных стилей. Существующие компоненты
сохраняются. Четыре чипа допускают перенос в существующем flex-wrap.
Тесты проверяют порядок, переходы, возврат по чипу/строке, сохранение полей,
очистку начала и восстановление pending. Отчёт:
[18-som-26](../../../app/review/18-som-26-schedule-time-step/README.md).
Внешний вид, нативные устройства и приёмка владельца остаются открытыми.
