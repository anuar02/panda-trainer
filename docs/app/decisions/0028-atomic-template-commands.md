# 0028. Атомарное сохранение шаблона и защита от устаревшей правки

- **Статус:** Принято
- **Дата:** 01.10.2026
- **Задача:** SOM-23

## Контекст

Основа библиотеки SOM-22 позволяла владельцу отдельно писать заголовок и строки
шаблона. При сетевом обрыве такой клиентский алгоритм мог оставить часть плана;
две правки могли последовательно затереть друг друга без проверки revision.

## Решение

save_workout_template сохраняет заголовок и весь состав одной транзакцией.
Порядок задаётся массивом JSON, позиция вычисляется сервером. Сохраняются подходы,
повторы или секунды (включая диапазоны), граммы, отдых и заметка. Шаблон содержит
1–50 разных упражнений своего workspace. Новому шаблону передаются null ID и
revision; существующему — ID и последняя прочитанная revision. Сервер блокирует
workspace, затем шаблон и отклоняет устаревшую правку с SQLSTATE 40001.

Состав заменяется целиком. ID шаблона сохраняется; ID строк состава пересоздаются.
Ссылки будущих программ/журналов должны использовать собственные снимки, а не ID
редактируемых строк. Триггеры состава повышают revision шаблона несколько раз;
клиент использует возвращённую revision и не вычисляет её как old + 1.
Ошибка любого элемента откатывает и заголовок, и все строки.

archive_workout_template выполняет ту же проверку revision и помечает archived_at,
сохраняя состав. Архивное упражнение остаётся допустимой ссылкой владельца при
редактировании или копировании; поиск библиотеки по-прежнему скрывает архив.
Запрет копирования такого шаблона не вводится без продуктового решения.

Успешные команды сохраняют приватный receipt по (workspace_id, request_id).
Повтор того же payload возвращает исходные ID/revision до проверки текущего
состояния; изменение payload или типа команды с тем же ключом отклоняется.
Receipt не читается через Data API. Возвращаемая при повторе revision — результат
той операции, а не обещание актуальности шаблона после последующих правок.

Прямая запись workout_templates/template_exercises закрыта, включая column-level
INSERT/UPDATE grants предыдущей миграции. Чтение владельцем сохраняется через RLS;
изменение самих exercises остаётся под правилами SOM-22. Правила записи ADR 0026
для шаблонов заменены этими командами.

## Границы и проверки

Этот пакет не переключает UI с локального хранилища на Supabase и не выбирает
провайдеры входа. Transport и восстановление сессии ждут SOM-60/SOM-19.
pgTAP проверяет доступ, порядок/единицы, откат некорректного состава, повтор,
архивирование и старую revision. template_concurrency.py проверяет два реальных
соединения: конкурирующая старая правка отклоняется; одинаковый request_id
возвращает один результат после ожидания блокировки. Команды — supabase/README.md.
