# 0035. Реальная библиотека и редактор шаблонов

- **Статус:** Принято технически; визуальная/native-приёмка открыта
- **Дата:** 01.10.2026
- **Задачи:** SOM-22, SOM-23

## Контекст

После входа и создания workspace доступны серверные упражнения и атомарные
команды шаблонов (ADR 0026/0028). Старые экраны используют e0…e80 и локальные
демо-шаблоны; такие ID нельзя отправлять в RPC вместо UUID.

## Решение

Отдельная группа `/workspace/library` использует те же Library, Template и
Editor компоненты с переданными данными и store. Демо сохраняет прежний provider.
Серверный UUID остаётся идентификатором упражнения/шаблона во всех операциях;
`source_key` используется только для сопоставления упакованных иллюстраций.

Поиск получает активные упражнения через `search_exercises`; локальные фильтры
сохраняют поведение прототипа. Шаблоны читаются со всеми упражнениями по UUID,
включая архивные ссылки. Архивирование меняет `archived_at`, не удаляет строки.
Своё упражнение создаётся из непустого поиска по существующему сценарию
`workout.createExercise`; по умолчанию повторения, не bodyweight, как у custom
упражнения прототипа. Отдельной неподтверждённой формы метаданных не добавляется.

INSERT упражнения не разрешает задавать ID. Повтор после потерянного ответа
находит активную строку с тем же нормализованным именем и принимает её только
при точном совпадении всех записываемых метаданных. Это `existing`, а не receipt
по request UUID; различающиеся данные дают ошибку дубликата.

Редактор сохраняет черновик в AsyncStorage под ключом пользователя и workspace.
Вместе с черновиком хранится исходная revision. Перед RPC сохраняется pending
payload с UUID запроса; после рестарта он восстанавливается для того же повтора.
Операция удерживает неизменный payload и не создаёт новый запрос при сетевой
ошибке, ошибке перечитывания или очистки черновика. После успешного RPC экран
перечитывает сервер и только затем очищает локальный черновик.

Операция сверяет текущую сессию с исходным пользователем и закрепляет её bearer
только в заголовке конкретного RPC. Переключение аккаунта во время запроса не
может перенести старый черновик в новый workspace. Токен не входит в сохранённый
pending payload. После размонтирования provider запрос, ожидающий локальную
запись, не отправляется.

Изменение черновика создаёт новый payload; старый неопределённый результат не
считается отменённым на сервере. Уникальность имени и expected revision не дают
молча создать дубль/затереть чужую версию. При конфликте черновик сохраняется,
замена серверной версией выполняется отдельным явным действием. Ошибка чтения
локального черновика блокирует запись, не перезаписывает повреждённые данные.

Килограммы переводятся в целые граммы, секунды отделены от повторений. Существующая
заметка строки сохраняется, nullable вес остаётся null при неизменённом нуле;
введённый новый вес имеет приоритет над прежним `plannedWeightG`.

## Границы

Применение шаблона к реальной программе/занятию — SOM-24/26; кнопка не запускает
демо-занятие из настоящего аккаунта. Избранное пока локальное состояние экрана.
Новые точки входа создания/архива и сообщения ошибок требуют визуальной
сверки/одобрения; готовность экранов не объявляется по одним тестам.
Проверки и точные результаты — в review-отчёте, ROADMAP и Linear.
