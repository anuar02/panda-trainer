# 0105. Общий вход экранов и предзагрузка вкладок

- Статус: принято для реализации; предзагрузка вкладок заменена [ADR 0113](0113-native-system-tabs.md); визуальная приёмка владельца открыта
- Дата: 04.10.2026
- Задача: SOM-39, бриф 14

## Решение

Существующий Reanimated переносит CSS prototype-fresh без новых библиотек.
MotionPolicyProvider объединяет синхронный системный snapshot, AccessibilityInfo
и сохранённый calm обеих ролей. Общий MotionScrollView анимирует блоки при focus,
повторяет вход при возврате и принимает motionKey для демо-сценария; обновления
данных не меняют revision. MotionHeader, MotionGroup, GrowX, MotionPressable,
TabMotion, PulseDot и Shimmer используют именованные токены motion.tsx.

Группы rows/invite подключаются явно; Card сохраняет собственный корневой
контейнер и gap. Native stack transition отключён: вход и возврат воспроизводит общий riseIn, без дополнительного platform slide.
Неактивные вкладки остаются lazy, но navigation.preload вызывается по одной
в idle-slot; без requestIdleCallback — после frame через timeout. Первый кадр
активной вкладки не ждёт предзагрузки остальных или сетевых запросов.

## Альтернативы и последствия

lazy:false перенёс бы все монтирования на первый экран и блокировал его старт.
Анимация непрозрачности всей сцены скрыла бы ступенчатый вход и не устранила
стоимость первого монтирования. Выбранные общие адаптеры сохраняют существующие
экраны, работу offline и layout; дополнительные wrapper layout properties
переносятся на внешний слот, горизонтальные ScrollView не оборачиваются.

Предзагрузка увеличивает память и раньше запускает эффекты вкладок; она отменяется
при смене navigator и не навигирует, не подтверждает записи и не ждёт данных.
Если пользователь нажмёт до idle-slot, экран всё ещё может монтироваться по требованию.
Измерения renderer не доказывают нативный frame budget или плавность на устройстве.
Маскот, журнал, тосты и шторки остаются в соседних брифах.
