# 0029. Назначение программы как новая неизменяемая копия

- **Статус:** Постоянное правило, одобрено владельцем
- **Дата:** 01.10.2026
- **Задача:** SOM-24; решение владельца по SOM-55 получено в разговоре

## Контекст

До ответа владельца действовало временное правило из OPEN-QUESTIONS №5: новая
копия программы, старая сохраняется. 01.10.2026 владелец подтвердил это как
постоянное правило по вопросу SOM-55. Правка библиотечного шаблона не должна менять
программу, по которой клиент уже занимался. Клиент не имеет прямого доступа к
библиотеке тренера, поэтому имя и техника упражнения должны быть доступны из
своей копии.

## Решение

client_programs хранит client_record_id, source template ID/revision, имя,
описание, собственные revision/audit. client_program_exercises хранит собственные
строки порядка и план, а также снимок имени, единицы, техники и метаданных
упражнения. Внешние ключи включают workspace, чтобы исключить чужого клиента,
шаблон или упражнение. Исходные ID остаются для происхождения; отображение
использует снимки и не требует чтения приватной библиотеки тренера.

assign_client_program определяет workspace по auth.uid() и проверяет ожидаемую
версию активного шаблона и активную карточку клиента. Транзакция копирует весь
состав. Повтор request_id возвращает исходный результат из приватного receipt;
тот же ключ с другим payload отклоняется. При stale revision новая копия не
создаётся. Все команды используют общий порядок блокировок: workspace, шаблон,
затем связанные строки источника.

При новом request_id создаётся новый ID программы. Предыдущие программы не
перезаписываются и не архивируются автоматически. Не добавляется понятие
«единственная текущая программа», merge или перенос изменений между копиями —
эти решения не входят в одобренное правило.

RLS разрешает владельцу читать программы своего пространства, клиенту — только
программы своей карточки и их строки. Участники одного пространства не видят
копии друг друга. Прямая запись программ/состава закрыта; пока доступна только
команда назначения. Правки и архив исходных шаблонов/упражнений не меняют снимок.

## Границы

Постоянное продуктовое правило не означает техническую готовность клиентского
transport, UI выбора программы, привязки к занятию или снимка отдельного журнала.
Не заявляется проверка двух телефонов или offline-синхронизации.
Проверки копий, прав и повторов — supabase/tests/database/client_programs.test.sql;
результаты и команды — supabase/README.md.

## Клиентский transport (01.10.2026)

`workspace-programs/service.ts` сохраняет исходные аргументы и пользователя
команды, проверяет сессию перед RPC и закрепляет Authorization за этой сессией.
Pending assignment хранится отдельно для пользователя/workspace/клиента до
отправки. Неизвестный результат повторяется с тем же request ID. Новая команда
не может заменить неразрешённую старую; повреждённая запись не удаляется молча.
Очистка условна по request ID. P0002 сервера отделён от локальной недоступности
сессии, чтобы UI не сбрасывал неопределённый запрос при смене аккаунта.

12 transport/storage тестов, TypeScript, ESLint и форматирование проходят.
Этот checkpoint не объявляет UI назначения подключённым или принятым.
