# 0031. Подтверждение и отмена отдельной записи

- **Статус:** Принято
- **Дата:** 01.10.2026
- **Задача:** SOM-27, первый серверный пакет

## Решение

confirm_booking принимает booking_id, expected_revision и request_id. Только
связанный клиент подтверждает свою предложенную запись. cancel_booking имеет
тот же контракт: клиент отменяет свою запись, владелец — запись своего workspace.
Роль определяется через auth.uid(), не передаётся вызывающим кодом.

Общий приватный обработчик блокирует workspace, затем booking и повторно
проверяет доступ. Устаревшая revision возвращает 40001 без изменения записи.
Заполненный finished_at связанного журнала запрещает смену статуса, как в
существующем scheduling domain. Подтверждение/отмена не меняют время занятия.

Приватный receipt имеет ключ workspace + actor + request_id. Payload связывает
команду, booking и ожидаемую revision; другой payload с тем же ключом отклоняется.
Повтор возвращает исходный результат до проверки текущего статуса/revision.
Подтверждение, повторённое после отмены, не возвращает booking в confirmed.

Отмена одного участника группы не меняет остальных и не удаляет group_session.
Ожидающие предложения этого booking получают withdrawn. Денежных операций нет:
позднее списание с причиной — отдельный сценарий, автоматические штрафы отложены.

## Проверки и границы

pgTAP проверяет роли, чужие ID, закрытые receipts, revision, повтор после смены
статуса, завершённый журнал и независимость участников группы. Два SQL-соединения
проверяют фактическое ожидание блокировки: устаревшая отмена не затирает
подтверждение, повтор подтверждения получает тот же результат.

Предложения/встречные предложения, согласование нового времени и явная команда
для всей группы ещё не реализованы. App transport, уведомления и проверка двух
телефонов остаются открытыми. Этот пакет не закрывает SOM-27 целиком.
