# 0100. Обновление личной программы после тренировки — по предложению тренеру

- **Статус:** Принято
- **Дата:** 04.10.2026
- **Кто решил:** владелец продукта

## Контекст

SOM-32. После тренировки фактические подходы могут отличаться от плана
(например, вырос рабочий вес). Личная программа — неизменяемая копия
([ADR 0029](0029-client-program-snapshots.md)): существующую копию нельзя
перезаписать. Временное правило до 04.10.2026: finish/correction меняют только
журнал, программа не обновляется. Эталон — задача 4 `prototype-fresh/CODEX-PLAN.md`.

## Решение

После завершения тренировки тренеру предлагается действие «Обновить программу».
Тренер выбирает упражнения, по которым переносятся фактические значения
(вес, повторы/время, число подходов). Подтверждение создаёт **новую** копию
личной программы клиента с этими значениями; предыдущая копия остаётся
в истории без изменений. Происхождение новой копии записывается: исходная
программа и ревизия, завершённый журнал и выбранные упражнения.

- Без подтверждения тренера программа не меняется; отказ ничего не создаёт.
- Повтор того же запроса идемпотентен (request_id), устаревшая ревизия исходной
  программы отклоняется без частичных строк.
- Исправление завершённого журнала (ADR 0090) само программу не меняет; тренер может
  снова предложить обновление после исправления.
- Клиент видит только итоговую актуальную копию и её историю, как сейчас.

## Рассмотренные варианты

- Не обновлять программу по итогам — отклонено: расходится с прототипом.
- Автоматическая новая копия после каждой тренировки — отклонено: без контроля
  тренера, засоряет историю копиями.

## Последствия

SOM-32 разблокирован: нужна новая migration (команда создания копии из журнала
с provenance и receipt), транспорт, экран выбора упражнений по прототипу и тесты
(pgTAP, concurrency, клиентские). Экран требует приёмки владельца.
