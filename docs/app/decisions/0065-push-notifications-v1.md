# 0065. Push-уведомления в первой версии

- **Статус:** Принято
- **Дата:** 03.10.2026
- **Кто решил:** владелец продукта

## Контекст

Вопрос №7 (SOM-57). Временное правило было «только уведомления внутри
приложения, push — после пилота» (ROADMAP, этапы 8 и 11). Владелец перенёс push
в первую версию.

## Решение

Push входит в v1 поверх ленты уведомлений этапа 8 (SOM-37). Четыре вида:

1. **Клиенту — напоминание о занятии** перед запланированным занятием
   (по умолчанию за 2 часа; настройку времени можно добавить позже).
2. **Клиенту — изменения расписания:** тренер подтвердил, перенёс или отменил
   занятие.
3. **Тренеру — запросы клиентов:** клиент запросил, перенёс или отменил занятие.
4. **Тренеру — план на день:** утренняя сводка занятий на сегодня в часовом поясе
   workspace.

Push — дополнительный канал, не замена: всё остаётся в ленте уведомлений
приложения. Если пользователь не дал разрешение или выключил push, он видит
уведомления только в приложении; повторно разрешение не запрашивается.

Голосовой ввод (вопрос №4) остаётся после пилота.

## Рассмотренные варианты

- Push после пилота — отклонено владельцем.
- Повторный запрос разрешения после первой записи — отклонено.

## Последствия

Нужны Expo push tokens по устройствам, их хранение с правами доступа, серверная
отправка из событий уведомлений и плановые задания для напоминаний и утренней
сводки. Push строится после ленты SOM-37. Сервис отправки Expo Push бесплатен;
платные сервисы — только с согласия владельца.
