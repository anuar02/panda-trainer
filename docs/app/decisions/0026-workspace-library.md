# 0026. Библиотека пространства и сохранение архивных ссылок

- **Статус:** Принято
- **Дата:** 01.10.2026
- **Задача:** SOM-22

## Контекст

Каталог прототипа содержит 81 упражнение. Тренеру нужна собственная копия,
пользовательские упражнения и поиск без различий регистра и ё/е. Архивирование
не должно удалять упражнение из уже созданного шаблона.

## Решение

exercises, workout_templates и template_exercises принадлежат workspace.
Составные внешние ключи связывают строки шаблона с упражнением и шаблоном в том
же пространстве. RLS разрешает доступ только владельцу; column grants защищают
идентификаторы, workspace при UPDATE, source_key, revision и audit-поля.
Физический DELETE упражнений и шаблонов недоступен authenticated. Строку состава
можно удалить при редактировании шаблона. Архив хранится в archived_at;
внешние ключи сохраняют старые ссылки и чтение архивного упражнения владельцем.

Нормализация приводит к нижнему регистру, заменяет ё на е и сворачивает пробелы.
Частичные уникальные индексы запрещают одинаковые активные названия внутри
пространства. Архивное имя можно использовать снова. Поисковая функция возвращает
только активные упражнения своего пространства. Пустой поиск возвращает каталог. Число либо диапазон повторов/секунд сохраняется
строкой, вес — целым числом граммов, отдых — секундами. Единица упражнения
недоступна для прямого UPDATE, чтобы не сделать сохранённый план несовместимым.
Изменение строки состава повышает и её revision, и revision шаблона.

Приватный общий каталог — снимок prototype-fresh/js/data.js с ключами и группами
из app/src/features/trainer-library/ru.ts. Сохраняются единицы, bodyweight,
aliases и инструкции. Медиафайлы не копируются и не публикуются заново.
После создания workspace SECURITY DEFINER-триггер копирует каталог с новыми UUID;
source_key связывает копию с исходным элементом. Миграция наполняет и существующие
пространства. Прямое выполнение функции копирования и доступ к private закрыты.
Изменение упражнения одного тренера не меняет общий каталог или чужую копию.

## Границы

Это серверная основа, а не переключение экранов с AsyncStorage на Supabase.
Производственный вход, клиентский transport, атомарное сохранение/переупорядочение
шаблона с проверкой revision (SOM-23) и снимки программ/журнала — отдельные задачи.
Минимум одно упражнение в готовом шаблоне и атомарность изменения состава
проверит команда сохранения; отдельная строка
не является завершённым пользовательским шаблоном. Нет утверждения о выполненной
проверке на двух телефонах или визуальном одобрении владельца.

Проверки и команды воспроизведения — supabase/README.md;
SQL-тесты — supabase/tests/database/library.test.sql.
