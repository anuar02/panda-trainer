# 0106. Выбранные WebP-клипы панды в крупных моментах

- Статус: решение владельца из брифа 05.10.2026 реализовано; визуальная и нативная приёмка открыты
- Задача: SOM-38
- Дополняет ADR 0005, 0060 и 0104

Владелец выбрал wave, thumbs, jump, sit, sleep, stretch, listen и анимированный
WebP через установленный expo-image. clipboard и front-idle отклонены.
Новые библиотеки, генерация и платные сервисы не нужны. Разрешение на бинарные
ассеты в app/assets/mascot/clips — прямое исключение владельца из ADR 0066;
скриншоты в git не добавляются.

Клип выбирается только по явному clipPlace и разрешённой для него позе.
Онбординг — wave/thumbs; celebration — jump; empty — sit/sleep;
invitation — wave/sit/thumbs; inbox-clear — sit; client-hero — wave.
Остальные вызовы сохраняют текущий PNG/Reanimated/Rive-путь.
Лица, аватары, тосты и rail не получают клипы. stretch и listen зарегистрированы
как ассеты/позы без экранного места: stretch в прототипе только в таблице поз,
голосового экрана v1 нет по SOM-54. Новое место или waiting-состояние не создаётся.

clipPlace не назначает Mascot.context. OPEN-QUESTIONS «SOM-38: контекст
PNG-маскота в спокойном интерфейсе» остаётся открытым. Существующая политика
видимости calm применяется первой: подтверждённые empty/onboarding допускают
статичный PNG, неизвестный context/hero/inline скрываются. Calm и системное
reduce motion никогда не монтируют WebP. Это сохраняет временное правило #76.

PNG-постер первого кадра клипа виден до onDisplay и после ошибки декодера.
Постер и WebP занимают один существующий бокс, contain/bottom center;
никакие размеры экранов не изменяются. При ошибке WebP удаляется.
При blur, размонтировании и inactive/background анимированный Image удаляется;
при возврате создаётся заново. cachePolicy=none исключает выбранный кеш
изображения; фактическое освобождение памяти SDWebImage/Glide/GPU нужно
проверить на устройствах. Глобальную очистку кеша не используем.

Празднование по-прежнему длится 2200 мс, с прежними fxPanda/fxFade,
confetti/spark и геометрией 170×200. Внутри этого окна играет jump, без
дополнительного PNG-hop. Полная петля jump длиннее окна и прекращается с ним.

Бюджет одного WebP — 300 000 байт. Сначала удаляем хвосты до естественной
границы цикла, проверяем пару последних/первых кадров; затем 12→10 fps,
затем quality 60→50→40. Исходные кандидаты и MP4 не меняются;
хромакей и общая обрезка уже выполнены исходным build_candidates.py.
Новая оптимизация работает только с выбранными animation.webp и сохраняет альфу.
Wave не имеет проверенного короткого полного жеста без скачка; даже quality 40
даёт 389 736 байт. По разрешённому в брифе исключению сохраняем лучший вариант
quality 60 / 10 fps / 445 248 байт. Остальные шесть укладываются в бюджет.
Точные параметры и все попытки — app/review/17-som-38-mascot-clips-integration/assets.json.

Web использует тот же WebP, а onError возвращает постер. API проверен по
установленным expo-image/src/Image.types.ts и ExpoImage.web.tsx и
[документации Expo SDK 57](https://docs.expo.dev/versions/latest/sdk/image/).
Нативное ощущение, FPS, память декодера и одобрение владельца не доказаны
экспортом и synthetic-тестами.
