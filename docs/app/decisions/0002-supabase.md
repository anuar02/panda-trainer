# 0002. Бэкенд — Supabase

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Кто решил:** владелец продукта

## Контекст

Данные реляционные: тренер → клиенты → занятия → журналы → подходы; пакеты и списания
требуют транзакций и строгих прав. Сравнение вариантов — `prototype-fresh/SYNC-DESIGN.md`.

## Решение

Supabase: Postgres, Auth, Row Level Security, RPC-функции, Realtime. Разработка —
локальный стек (`supabase start`) и бесплатный облачный проект с вымышленными данными.

## Рассмотренные варианты

- **Firebase / Firestore** — готовый офлайн-кэш, но last-write-wins на документе может
  молча потерять подход; сложнее транзакции по пакетам и связи.
- **Свой API + Postgres** — полный контроль над размещением, но сервер нужно
  сопровождать; для старта дорого.

## Последствия

- Права проверяются в базе (RLS), бизнес-правила денег — в SQL-функциях с тестами pgTAP.
- Офлайн для журнала делаем сами ([ADR 0003](0003-offline-sync.md)).
- В списке регионов Supabase нет Казахстана. Вопрос о размещении реальных данных
  отложен ([OPEN-QUESTIONS](../OPEN-QUESTIONS.md) №1); при необходимости возможен
  self-hosted Supabase в выбранной стране без переписывания приложения.
- Pro-тариф ($25/мес) понадобится к пилоту (бэкапы, отсутствие паузы проекта).
