# 0006. Каркас приложения и воспроизводимые проверки

- **Статус:** Принято
- **Дата:** 29.09.2026
- **Кто решил:** исполнитель этапа 1 в рамках согласованного плана

## Контекст

Нужен отдельный Expo-проект без изменения корневого Higgsfield CLI. Этап 1 должен
проверять навигацию, тему и компоненты до появления авторизации и предметной схемы.

## Решение

- Expo SDK 57 и совместимые версии через `expo install`; NativeWind 4.2.7 и Tailwind 3.
  NativeWind 5 пока RC, SDK 58 — beta: prerelease не используем.
- Expo Router: маршруты в `app/app/`, две группы вкладок и временный выбор роли.
  Никакого признака авторизации или доступа из выбранной роли не выводим.
- Общий JSON токенов питает Tailwind и нативные API, которые принимают только `style`
  (навигация и bottom-sheet). Остальные стили — классы NativeWind.
- Взята палитра «Чернила» из `prototype-fresh/css/tokens.css` и `theme-dark.css`.
  Светлый success затемнён до `#08751e`, warning — до `#805a08`, граница контролов —
  `#82827d` (затемнённая граница строгого варианта); тёмные текстовый accent `#8c9eff` и граница
  контролов `#84858d`. Это обеспечивает AA на используемых поверхностях.
- Общий Text объединяет конфликтующие классы через `tailwind-merge` 2.6
  (Tailwind 3): цвет подписи на заливке не зависит от порядка CSS-правил.
- Статические начертания Inter и Montserrat через `@expo-google-fonts/*` и `expo-font`.
  Они включены в бандл и не требуют доступа к Google при запуске.
- i18next + react-i18next, русские ресурсы и типизированные ключи; язык пользователя
  не угадываем. Постоянное хранение настройки темы пока не добавляем.
- ESLint запрещает `any`, комментарии и прямой текст JSX; Prettier входит в `check`.
  Генерируемые Expo/NativeWind декларации исключены из запрета комментариев, ручная
  декларация NativeWind использует import вместо triple-slash.
- Jest + React Native Testing Library проверяют действия и доступность;
  `test-renderer` закреплён на 1.2.0: версия 1.3 требует React 19.3, а SDK 57 использует 19.2.3; отдельный тест
  проверяет контраст текста и границ контролов. Бандлы проверяются Metro для всех платформ.
- Supabase CLI — фиксированная devDependency приложения; `npm run db -- …` выбирает
  корень репозитория через `--workdir ..`. Первая миграция — пустая исходная точка.
  pgTAP guard отклоняет публичные таблицы без RLS; предметные политики и тесты — этап 2.

## Варианты и последствия

Рассмотрены prerelease NativeWind 5/SDK 58 и копирование браузерного прототипа;
выбраны стабильные пакеты и нативные компоненты согласно этапу 1.
Выбор роли обратим и будет заменён потоком входа. `/review` доступен только в development.
Новые хранилища, формы и сеть не подключены до первого использующего их модуля.

Обёртка шторки отслеживает факт открытия и сбрасывает его до `onClose`.
Это предотвращает `dismiss()` до первого `present()` и повторный `dismiss()`
после жеста; иначе Bottom Sheet 5.2.14 остаётся в состоянии DISMISSING
([upstream #2669](https://github.com/gorhom/react-native-bottom-sheet/issues/2669)).
Сценарии закрытия и повторного открытия проверяются unit-тестами.
