# 0017. Русские множественные формы в native

- **Статус:** Принято
- **Дата:** 30.09.2026
- **Кто решил:** исполнитель по результату Android smoke

## Проблема

На Pixel 9 / Expo Go 57 вместо «4 подхода» отображался ключ `workout.sets`.
Web и Node-тесты проходили, поэтому отсутствие native plural rules оставалось
незамеченным. В установленном i18next `PluralResolver.getRule` при ошибке
`Intl.PluralRules` возвращает правило one/other, не русское one/few/many.

## Решение

Закреплён `@formatjs/intl-pluralrules` 6.3.15. До инициализации i18next подключены
`polyfill-force.js` и только русские locale-data. Применяется документированный
[вариант для React Native/Hermes](https://formatjs.github.io/docs/polyfills/intl-pluralrules/#react-native),
без медленного conditional detection. Один механизм используется всеми экранами,
не добавляются неверные fallback-строки или ручные склонения в каждом компоненте.

Jest сохраняет preset Expo и дополнительно преобразует ESM пакеты `@formatjs`,
поэтому регрессия проверяет настоящий polyfill, а не mock. Проверяются 1/2/5/11/21/24
и общие подписи расписания/библиотеки. Остальные языки не добавлены.

## Последствия

Небольшая зависимость и загрузка правил до ресурсов. Повторные exports трёх
платформ и native smoke прошли: Android показывает «3 подхода», iOS открывает
журнал без ошибки. npm install сообщил 14 moderate advisories во всём
dependency tree, автоматический `audit fix` не запускался. Отдельный аудит дерева
не является частью этой локальной исправляющей задачи.
