# Правила разработки

Для людей и агентов (Claude, Codex). Правила из `AGENTS.md` действуют дополнительно.

## Код приложения (`app/`)

- TypeScript strict; `any` запрещён, при неизвестном типе — `unknown` и сужение.
- **Комментарии в коде не пишутся.** Объяснения — в именах, типах и документации.
- Только функциональные компоненты и хуки. Производное состояние вычисляется, а не
  хранится.
- Стили — классы NativeWind в разметке; цвета и размеры только из темы, без «магических»
  значений.
- Все строки интерфейса — через i18n (`i18n/ru.ts`).
- Доступность: `accessibilityLabel` у кнопок-иконок, сенсорные цели от 44×44,
  контраст WCAG AA, поддержка системного масштаба шрифта и уменьшения движения.
- Бизнес-правила — в `src/domain/` чистыми функциями с unit-тестами.
- Сеть — только через хуки модуля; экраны не вызывают `supabase` напрямую.

## База (`supabase/`)

- Изменения схемы — только новой миграцией (`supabase migration new <имя>`), старые
  миграции не редактируются после попадания в `main`.
- Каждая новая таблица: RLS включён в той же миграции, политики и pgTAP-тест в том же PR.
- Каждая RPC с деньгами или списаниями: тест на повтор и параллельный вызов.
- SQL можно комментировать там, где правило неочевидно (блокировки, идемпотентность).
- После изменения схемы — перегенерировать `database.types.ts`.

## Ветки, коммиты, PR

- Ветка от `main`; одна задача плана — один PR.
- Сообщение коммита — по-английски, в повелительном наклонении: `Add booking overlap warning`.
- PR заполняется по шаблону `.github/pull_request_template.md`.
- Зелёный CI обязателен до слияния.
- Секреты, ключи и реальные данные клиентов не попадают в репозиторий.

## Документация и учёт изменений

В каждом PR, где меняется код, схема или поведение:

1. **`CHANGELOG.md`** — строка в «Не выпущено» в нужной группе
   (Добавлено / Изменено / Исправлено / Удалено / Документация), со ссылкой на PR.
2. **`docs/app/ROADMAP.md`** — отметить выполненные пункты `[x]` и обновить
   «Где остановились» (дата, этап, что сделано, следующий шаг).
3. **ADR** в `docs/app/decisions/`, если:
   - добавлена библиотека, которая меняет устройство (хранилище, навигация, стили, сеть);
   - изменено бизнес-правило или правило доступа;
   - выбран один из нескольких разумных вариантов.
   Отменённое решение не удаляется: статус меняется на «Заменено ADR NNNN».
4. **`OPEN-QUESTIONS.md`** — новый вопрос, если задача требует решения владельца;
   закрытый вопрос переносится вниз со ссылкой на ответ.
5. Справочные документы (`ARCHITECTURE.md`, `DATA-MODEL.md`, `app/README.md`,
   `supabase/README.md`) — если изменилось устройство.

Правило для агентов: не угадывать продуктовое решение. Записать вопрос в
`OPEN-QUESTIONS.md`, сделать безопасный обратимый вариант и явно сказать об этом в PR.

## Версии и релизы

- Версия приложения — SemVer в `app/app.json`. До пилота — `0.x`.
- При сборке для тестировщиков раздел «Не выпущено» в `CHANGELOG.md` переименовывается
  в версию с датой, и создаётся новый пустой «Не выпущено».
- Номер сборки EAS растёт автоматически.

## Проверка перед PR

```sh
cd app && npm run check       # typecheck + lint + unit
supabase test db              # права и бизнес-правила
```

Изменения экранов — снимки iOS и Android (или эмулятора) в `app/review/<задача>/`
и ссылка в PR. Что не проверено на настоящем телефоне — написать прямо.

## Паритет с прототипом

Обязателен для каждого PR, который добавляет или меняет экран или компонент.
Полные правила — [UI-PARITY.md](UI-PARITY.md). Коротко:

- Эталон — `prototype-fresh/index.html` без параметров, 390 × 844, тема по роли.
- Числа — из `prototype-fresh/review/parity/spec-*.json`, не «на глаз».
  Значение в `tokens.json`, которого нет в спецификации, — ошибка ревью.
- Тексты — дословно из прототипа; иконки — набор прототипа; компоненты — из `src/ui/`.
- В PR: пары «эталон | приложение» по всем темам и состояниям экрана в
  `app/review/<задача>/parity/` и заполненный чек-лист UI-PARITY §6.
- Отклонение — только из таблицы UI-PARITY §5; новое — с причиной и согласия владельца.
- После одобрения — обновить статус экрана в UI-PARITY §7.
