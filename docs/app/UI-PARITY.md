# Паритет интерфейса с прототипом

Решение владельца, 29.09.2026 ([ADR 0007](decisions/0007-ui-reference.md)): приложение
выглядит **как `prototype-fresh/index.html`, открытый без параметров**. Экран, который не
совпадает с эталоном, не считается готовым, даже если он работает.

## 1. Что является эталоном

| Параметр | Эталон | Не эталон |
| --- | --- | --- |
| Оформление | вид по умолчанию (без `?visual=`) | `?visual=instrument`, `?visual=firm` |
| Палитра | «Чернила» (без `?palette=`, акцент `#2b48d6`) | `teal`, `panda` |
| Тема | «По роли»: тренер — тёмная, клиент — светлая, журнал тренировки — всегда тёмный | системная тема телефона по умолчанию |
| Ширина | 390 × 844 (телефон) | 1440 и широкий кабинет — после пилота |
| Данные | демо-данные прототипа (`prototype-fresh/js/data.js`), время `?now` не задаётся | — |

Тема в профиле: «Авто (по роли) / Тёмная / Светлая», выбор сохраняется на устройстве.
Журнал тренировки тёмный при любом выборе.

Старые снимки в `prototype-fresh/review/*` (кроме `parity/`) — история. Сверять только
со снимками, снятыми скриптом ниже.

## 2. Эталонные снимки и замеры

`prototype-fresh/review/parity/capture.cjs` открывает прототип без демо-панелей
(`?present`), проходит 19 экранов × 4 состояния (`normal`, `empty`, `loading`, `offline`)
в теме «по роли» и все экраны в тёмной и светлой, снимает 390 × 844 @2x.

```sh
npm ci                                                   # из корня: @playwright/test
python3 -m http.server 4187 --bind 127.0.0.1 --directory prototype-fresh &
node prototype-fresh/review/parity/capture.cjs          # SCREENS=t-today,c-home — выборочно
```

- PNG → `prototype-fresh/review/parity/reference/` (в git не попадают, ~30 МБ).
- `spec-light.json`, `spec-dark.json` (в git) — **вычисленные браузером** CSS-переменные
  и стили каждого класса: шрифт, кегль, начертание, межстрочный, цвет, фон, радиус,
  отступы, высота, тень. Это источник чисел для токенов и компонентов. Числа не
  подбираются «на глаз» по картинке — они берутся отсюда.
- Если прототип изменился — перезапустить скрипт и закоммитить новые `spec-*.json`.

Прототип не редактируется ради приложения. Меняется только `review/parity/`.

Поправка захвата 29.09.2026: режим `?present` сжимал рамку до 390 × 768 при
viewport 390 × 844. Скрипт теперь фиксирует только высоту рамки устройства и
проверяет её bounding box; продуктовые стили не меняются. Частичные запуски
для сравнения задают `SPEC_DIR` внутри каталога результата, чтобы не перезаписать
полные эталоны неполной выборкой. `npm run parity` в `app/` делает это автоматически.

Уточнение детерминизма 29.09: перед снимком и замерами конечные CSS-анимации
доводятся до конца, бесконечные ставятся на паузу в начале. Иначе задержка 250 ms
снимала нижние строки во время riseIn (opacity около 0.89 и временный translateY).
Это стабилизация инструмента, а не изменение прототипа. Motion проверяется отдельно.

## 3. Правила переноса

1. **Токены — один в один.** Цвета, радиусы, кегли, начертания, межстрочные, отступы и тени
   из `spec-*.json` переносятся в `app/src/ui/tokens.json` без округления. Отличие
   допустимо только если автоматическая проверка контраста (AA) не проходит; тогда
   значение подбирается минимально и записывается в таблицу отклонений (§5).
2. **Шрифты и начертания.** Montserrat и Inter в тех начертаниях, которые реально
   встречаются в `spec-*.json`: сейчас Inter 400, 500, 550, 600, 650, 700, 750, 800 и
   Montserrat 400, 700, 800. Своих начертаний не добавлять, нужных не пропускать.
   Промежуточные 550/650/750 — через переменный Inter, если он одинаково работает на
   iOS и Android; иначе округление вверх до статического (550→600, 650→700, 750→800),
   записанное в §5.
3. **Иконки.** Набор из `prototype-fresh/js/icons.js` (24×24, штрих 2, скругления),
   перенесённый в `react-native-svg`. Толщина активной вкладки — как в прототипе (2.3).
   Сторонние наборы (Feather и т.п.) не используются.
4. **Тексты — дословно.** Все строки берутся из прототипа, включая склонения, «ё»,
   неразрывные пробелы и переносы (`Распи­сание`). Меняет текст только владелец.
5. **Структура экрана.** Порядок блоков, их состав, группировка и что видно без прокрутки
   — как в эталоне. Нельзя «упростить» блок, убрать счётчик, бейдж или вторичную строку.
6. **Состояния.** Для каждого экрана реализуются все четыре состояния эталона: обычное,
   пустое (с пандой, где она есть), загрузка, «нет сети».
7. **Компоненты — из общего набора** `app/src/ui/`, каждый соответствует классу прототипа
   (§4). Экран не рисует свою версию кнопки, карточки или строки.
8. **Маскот.** Те же PNG из `prototype-fresh/assets/mascot/`, те же места и размеры.
   Rive — по [ADR 0005](decisions/0005-mascot-motion.md), не меняя размеры и места.
9. **Движение.** Длительности из токенов прототипа (`--dur-*`). При «уменьшении
   движения» и в «Спокойном интерфейсе» — как в прототипе.

## 4. Набор компонентов

Таблица заполняется в PR, который создаёт компонент. Колонка «Класс» — ключ в
`spec-*.json`.

| Компонент приложения | Класс прототипа | Где встречается | Статус |
| --- | --- | --- | --- |
| `TabBar` (плавающая, 5 вкладок, счётчик) | `tabbar`, `tabbar__item`, `is-on`, бейдж на «Сегодня» | все экраны ролей | перенесена частично; badge/blur/motion открыты |
| `Button` primary (синий градиент + тень) | `btn`, `btn--primary` | «Начать тренировку», формы | перенесена; приёмка открыта |
| `Button` secondary / compact / icon | `btn`, `btn--*` | — | перенесены; приёмка открыта |
| `Card` | `card` (`--r-card` 24, `--shadow-card`) | везде | перенесена; приёмка открыта |
| `Chip` | `chip` | фильтры, выбор | проверить |
| `ScreenHeader` (приветствие, заголовок, дата, действия) | `today-head*` | «Сегодня» | перенесён; приёмка открыта |
| `HeroSummary` (тёмная карточка с пандой) | см. «Сегодня» | «Сегодня» | демо перенесено, без motion |
| `TimelineRow`, `FreeSlotRow` | строки плана дня | «Сегодня», «Расписание» | демо перенесено; приёмка открыта |
| `Sheet` | `sheet`, `sheet__grip` (`--r-sheet` 32) | везде | не совпадает |
| `Toast` | `toast` (`--r-toast` 20) | везде | проверить |
| `StatusPill`, `CountBadge` | `pill`, бейджи счётчиков | везде | StatusPill перенесён; badge вкладки открыт |
| `SetRow`, журнал | классы с `firstSeenOn: "t-session"` в `spec-dark.json` | журнал, частично реализован | не принят |

Остальные компоненты добавляются в таблицу по мере переноса экранов.
