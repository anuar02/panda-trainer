# Команда переноса прототипа

Владелец разрешил четыре агента 29.09.2026: координатор и три исполнителя.
Исполнители стартуют без истории разговора, получают одну ограниченную задачу.
При смене подсистемы — новый контекст, а не накопление всей истории.

## Текущая волна

30.09 — новая волна журнала со свежими контекстами: workout_domain владеет
`domain/workout` и domain-тестами; workout_ui — `features/workout` и UI-тестами;
workout_entrypoints — Today/Schedule и тестами переходов. Координатор — provider,
маршрут, dock, глобальная регистрация, capture и docs. После первичных handoff
первому переданы dock/его тесты, третьему — только тесты provider. История других
подсистем исполнителям не передаётся; общие API согласованы коротким контрактом.

Предыдущие волны (завершены):

Checkpoint журнала: все три исполнителя завершили задачи; root интегрировал
API через публичный `workout-demo` (включая `useJournalLabels`), исправил web SVG
transform и выполнил полный capture. Следующую подсистему начинать свежими
контекстами, не форкать длинные рабочие ветки. Проверки и пробелы — ROADMAP.

| Владелец | Запись только в | Задача |
| --- | --- | --- |
| shared_ui | `app/src/ui/` кроме icons, корневой layout, tailwind, shared-parity tests | Шрифты и общие компоненты |
| trainer_today | `features/trainer-today`, маршрут today, trainer-today tests | Сегодня: четыре состояния, локальные детали |
| client_home | `features/client-home`, маршрут home, client-home tests | Главная: четыре состояния, локальные отмена/отзыв |
| Координатор | i18n registry, demo hook, capture, assets, документация | Интеграция, проверки, следующий пакет задач |

Все читают обязательные правила проекта самостоятельно, используют graft до
чтения исходников. Изменения общей API согласовываются короткими сообщениями.
Глобальные файлы и коммиты остаются у координатора. Никаких новых backend/auth
решений, реальных данных или платных сервисов.

## Контракт handoff

Checkpoint 30.09: волны и визуальные исправления интегрированы; активных
исполнителей этого пакета не осталось. Финальные результаты — в ROADMAP и отчёте
foundation-parity. Следующий пакет запускается со свежими контекстами после
определения общего демо-состояния; старые длинные ветки исполнителей не форкать.

Первая волна интегрирована и проверяется координатором. Сохранены компактные
результаты; новая волна стартовала без истории предыдущих исполнителей:

| Владелец | Запись только в | Задача |
| --- | --- | --- |
| trainer_schedule | `features/trainer-schedule`, маршрут schedule, одноимённые tests | Неделя/даты/демо-расписание |
| client_program | `features/client-program`, маршрут program, одноимённые tests | Программа и детали упражнений |
| client_history | `features/client-history`, маршрут history, одноимённые tests | История и списания |

Координатор по-прежнему владеет общей регистрацией i18n, assets, capture и docs.

Третья волна также получила свежие контексты без истории: trainer_clients —
каталог клиентов и фильтры; trainer_library — 81 упражнение, 4 шаблона и
read-only детали; client_progress — каноническое состояние без записанных
подходов и недельная сетка. Каждому принадлежат только его feature, route и tests.
После них profiles переносит оба профиля, а отдельный read-only visual_audit
сравнивает Clients/Library/Progress. Одновременно не более трёх исполнителей.

После задачи: файлы, экспортируемая API, выполненные проверки, точные пробелы,
следующее действие. Не пересказывать всю историю и не загружать несвязанные файлы.
Снимки и тесты — свидетельства, не одобрение паритета владельцем.

Для этой волны недоступные входящие/создание/журнал и предложение переноса
не подменяются фиктивным успехом; контроль недоступен до реализации сценария.
Это известная незавершённость, не принятое отклонение от прототипа.
