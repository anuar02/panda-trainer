# Руководство по прототипу

## Как открыть

Зависимостей и сборки нет — это статические HTML/CSS/JS:

```bash
open prototype/index.html
# или
python3 -m http.server 8000   # http://localhost:8000/prototype/
```

Шрифты (Inter, Montserrat) подгружаются с Google Fonts. Без сети интерфейс
останется работоспособным на системных шрифтах.

## Оболочка

| Зона | Что делает |
| --- | --- |
| **Рельса слева** | индекс экранов; счётчик активных запросов у «Входящих»; сброс прототипа |
| **Центр** | устройство: переключатель роли, состояния, ширина, широкий вариант |
| **Инспектор справа** | правила текущего экрана и счётчики проверки |

Переключатели сверху:
- **Роль** — Тренер / Клиент.
- **Состояние** — Обычный день · Пустой день · Загрузка · Нет связи.
- **Ширина** — 375 / 390 / 430 px (требование handoff v2).
- **Широкий** — широкий вариант «Сегодня» для тренера.

## Сценарии для проверки

Ниже — как воспроизвести критерии приёмки из handoff v2 (§13).

### Перенос (обе роли)
1. Тренер → Входящие. Видны два запроса. У Айгерим: действует `чт 17 сен 18:00`,
   предложено `пт 18 сен 19:00`, «Ждёт вас».
2. **Принять** → занятие Айгерим переезжает на пятницу 19:00, запрос уходит в историю.
3. Вместо принятия можно **Другое время** → встречное предложение; ответственный
   меняется на клиента.
4. **Отклонить** / **Отозвать** → действует прежнее время, тост об этом.
5. Клиент → Главная: под карточкой видно и действующее, и предложенное время и
   чей ответ ожидается. Кнопка **Отозвать запрос** доступна автору.
6. Клиент **Предложить перенос** (когда активного запроса нет) → выбрать дату и
   время → **Отправить запрос**. До подтверждения время не меняется.

Что проверяем: клиент отличает действующее время от предложенного; перенос без
ответа не меняет время; повторное действие не дублируется.

### Проведение тренировки и участники
1. Сегодня → у мини-группы 20:00 **Провести группу**.
2. Внизу — переключатель участников: Алия 0/16, Мади 2/13, Дана 0/12.
3. Переключите Алия → Мади → Дана. Введённое у Мади сохраняется, к Дане не
   переносится (изоляция данных по участнику).
4. **Записать** любой подход → шторка с крупным числом; **Повторить прошлый
   результат** подставляет значение из прошлого раза.
5. **Завершить тренировку** с незаписанными подходами → шторка с выбором
   «Сохранить записанное и завершить» / «Продолжить ввод». Незаполненное не
   становится нулём.

### Посещение и списание (идемпотентность)
1. Клиенты → Арман → любое занятие → шторка занятия.
2. **Пришёл** → шторка «Отметить посещение?» с последствием: «списать 1 занятие».
3. **Отметить и списать** → тост, движение занятий увеличивается на одну запись.
4. Повторите нажатие (через повторное открытие) — второй операции не создаётся;
   приходит предупреждение «Уже списано».

### Ошибка сохранения
1. Состояние **Нет связи**.
2. Открыть тренировку, записать подход, **Завершить тренировку**.
3. Ввод сохраняется, индикатор становится «Не сохранено · черновик на устройстве»,
   кнопка — «Повторить сохранение». Успех не подделывается.

### Прочее
- **Пустой день**: объяснение и «Добавить занятие».
- **Загрузка**: скелетоны.
- **Приглашение**: переключите состояния ссылки и убедитесь, что истёкшая и
  отозванная ссылка ведут к понятному пути, а принятая — не раскрывает данные.
- **Прогресс**: при одной записи тренд не рисуется; незаписанное не равно нулю.

## Модель состояний переноса

```
pending ──accept──▶ accepted      (единственное, что меняет время занятия)
   │
   ├─decline──▶ declined          (действует прежнее время)
   ├─withdraw─▶ withdrawn         (автор отозвал)
   ├─counter──▶ counter ──accept─▶ accepted
   └─stale────▶ stale             (уведомление открывает актуальное, не повторяет)
```

Правила: запрос без ответа не меняет время; отмена записи закрывает её ожидающий
перенос; устаревшее уведомление не повторяет действие.

## Что смоделировано, а что нет

Смоделировано без бэкенда:
- задержка сохранения ~550 мс и ошибка при «Нет связи»;
- идемпотентность списания через ключ `charge:session:client`;
- изоляция значений по участнику в `state.logging.values[clientId]`.

Не реализовано намеренно (отложено в handoff v2 §10): приём платежей, push,
QR, чат, автоматические штрафы, офлайн-синхронизация, роли клуба. Плюс
возможность редактировать результаты клиентом — открытый вопрос.

## Где менять UI/UX

- Токены: `prototype/css/tokens.css`.
- Повторяемые компоненты: `prototype/css/components.css`.
- Разметка экрана: `prototype/js/screens/*.js`.
- Шторки и их копирайт: `prototype/js/sheets.js`.
- Логика и состояния: `prototype/js/store.js`.
- Данные: `prototype/js/data.js`.

Порядок подключения скриптов в `index.html` важен: `icons → data → store → ui →
sheets → screens → app`.
