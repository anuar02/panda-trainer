Аккаунт third (Pro): разрешено использовать субагентов по SUBAGENTS.md.

## Решения владельца 04.10.2026 (действуют для этого брифа)

1. Новые изображения и клипы — **кандидаты на одобрение**: складываются в
   `design-exploration/mascot-motion-2026-10-04/`, в приложение НЕ подключаются.
   Подключение — отдельный бриф после выбора владельца.
2. Видео — источник, итог — **покадровые анимации с прозрачностью**: видео
   генерируется, затем из него извлекаются кадры. Прозрачное видео в нативное
   приложение не идёт (ADR 0005 остаётся в силе).
3. Исключение из RULES/ADR 0066 только для этой папки: можно коммитить
   ассеты-кандидаты (PNG/WebP кадры, контакт-листы). Снимки экранов по-прежнему
   не коммитить. Держать размер разумным (см. ниже).
4. Higgsfield: владелец разрешил использовать подключённый Higgsfield (приложение/
   коннектор аккаунта Codex). Бюджет: не больше 8 видео-генераций и 16 генераций
   изображений за задачу. Перед началом проверить баланс и записать в отчёт
   потраченные кредиты. Ключи/токены никогда не печатать и не коммитить.
   Если Higgsfield в контейнере недоступен — выполнить только Этап 1, этапы 2–3
   оформить как готовые промпты/скрипты и явно написать «не сгенерировано».

## Этап 1 — кадры из уже одобренных видео (без затрат)

Одобренные владельцем ролики 28.09: `design-exploration/mascot-video-2026-09-28/out/
<pose>-raw.mp4` для wave, thumbs, jump, clipboard, sit, sleep, stretch; конвейер
хромакея — `key_video.sh` и `CODEX-VIDEO-HANDOFF.md` там же (у jump хвост
перескакивает — владелец сказал «пойдёт», не перегенерировать).
ffmpeg в контейнере нет: использовать `npx ffmpeg-static` или
`pip install --user imageio-ffmpeg` (как в key_video.sh), без root.

Для каждой позы:
- зацикленный фрагмент (найти точку петли без скачка; если петли нет —
  ping-pong или один проигрыш, указать в отчёте);
- кадры с альфой 12 fps, ширина 320 px; без зелёной каймы (despill);
- итоговые форматы для сравнения: (а) анимированный WebP с альфой — expo-image
  уже собран с SDWebImageWebPCoder и проигрывает его на iOS/Android;
  (б) спрайт-лист PNG/WebP + JSON (кадр, размер, fps) для Reanimated-проигрывателя;
- размер: цель ≤ 300 КБ на позу в формате (а); если не выходит — указать, сколько
  и за счёт чего (fps/кадры/размер);
- контакт-лист кадров и первый/последний кадр рядом (проверка петли).

## Этап 2 — новые моменты (Higgsfield)

Чего нет среди одобренных клипов, но есть в эталоне prototype-fresh:
- front idle (спокойное дыхание, петля) — главный экран/пустые состояния;
- празднование после тренировки (эталон `.fx-panda`, fresh.css:750-806);
- голос: слушает / думает / пожимает плечами (fresh.css:1248-1253, pandaListen,
  pandaThink, pandaShrug).
Порядок: ключевой кадр из утверждённого PNG позы (через image generation только
если позы нет; иначе использовать PNG как есть) на хромакее `#00B140` 1024²
(`make_keyframes.py`), затем image-to-video с короткой петлёй 4–6 с, затем Этап 1.
Промпты сохранить в `prompt-<moment>.txt`. Выбор модели — лучшая доступная для
image-to-video с сохранением персонажа; записать модель и параметры.

## Этап 3 — страница сравнения для владельца

`design-exploration/mascot-motion-2026-10-04/index.html` (без внешних зависимостей):
для каждой позы/момента — анимированный WebP на светлом и тёмном фоне в реальных

fps, петля. Владелец выберет по этой странице.
