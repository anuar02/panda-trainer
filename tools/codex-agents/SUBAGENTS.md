## Работа с субагентами

У этого аккаунта есть запас лимита — используй субагентов (multi-agent), чтобы
выполнить задачу быстрее. Ты — ведущий агент.

- Не больше трёх субагентов одновременно. Запускай их с чистым контекстом
  (`fork_turns: "none"`) и давай полный самодостаточный бриф: путь к репозиторию,
  правила из этого промпта, решения владельца, контракты и как проверить результат.
- Каждому субагенту — узкая часть задачи и исключительное владение файлами.
  Два субагента никогда не правят один файл.
- Ведущий владеет общими файлами (маршруты, i18n, `database.types.ts`,
  `CHANGELOG.md`, `docs/app/ROADMAP.md`, ADR), интеграцией, финальной проверкой и
  коммитами. Субагенты эти файлы не трогают, если ты явно не поручил.
- В контейнере 2–3 CPU и ограниченная память: тяжёлые команды (`npm run check`,
  полный jest) запускает только ведущий; субагенты гоняют только свои тесты
  (`npx jest <файл>`).
- Требуй от субагентов конкретный отчёт: изменённые файлы, точные команды и
  результаты тестов. Проверяй каждый результат сам — фокусные тесты субагента не
  заменяют финальную проверку.
- Хорошие роли: реализация отдельной подсистемы; независимое ревью (SQL и права,
  UI против прототипа, изоляция аккаунтов и точность денег); написание тестов.
- Если субагент упёрся в лимит или завис — сохрани его файлы, доделай сам или
  другим субагентом. Не останавливай всю задачу из-за одного субагента.
