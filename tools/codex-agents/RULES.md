# Общие правила для автономного агента

Эти правила добавляются к каждому брифу задачи. Владелец не отвечает на вопросы
во время работы — работай полностью автономно.

## Перед началом

1. Прочитай `AGENTS.md`, `docs/app/README.md`, раздел «Где остановились» в
   `docs/app/ROADMAP.md`, `docs/app/CONVENTIONS.md`, `docs/app/UI-PARITY.md`,
   `docs/app/PROJECT-MEMORY.md` и `docs/app/decisions/0007-ui-reference.md`.
2. Если установлен `graft`, ориентируйся через `graft ask "<задача>" --source`.
3. Эталон — `prototype-fresh/index.html`; числа — `prototype-fresh/review/parity/spec-*.json`.

## Во время работы

- Никогда не задавай вопросов. Неясное продуктовое решение — запиши в
  `docs/app/OPEN-QUESTIONS.md`, примени действующее временное правило или самый
  безопасный вариант и продолжай.
- Меняй только файлы своей задачи (раздел «Границы» брифа). Параллельно работают
  другие агенты; общие файлы трогай минимально.
- Код в `app/`: без комментариев, TypeScript strict, без `any`, строки через i18n.
- Не подключай платные сервисы и реальные данные клиентов.
- Не коммить новые PNG и другие снимки экранов (ADR 0066): в git — только текстовый
  отчёт проверки; снимки оставь вне коммита.
- Не меняй Linear, не пиши комментарии и сообщения людям.

## Перед завершением

1. `cd app && npm run check` — должен быть зелёным. Почини все ошибки.
2. Добавь строку в `CHANGELOG.md` («Не выпущено») и отметь прогресс в
   `docs/app/ROADMAP.md`. Новый выбор библиотеки или подхода — ADR в `docs/app/decisions/`.
3. Сохрани отчёт проверки в `app/review/<имя-задачи>/README.md`: точные команды,
   результаты и что не проверено (например, нативные устройства).
4. Закоммить, затем `git push -u origin {{BRANCH}}`.
5. `gh pr create --base {{BASE}} --draft --fill`. В описании PR перечисли критерии задачи
   с отметкой «сделано / не проверено / требует одобрения владельца».
6. Не объявляй экран принятым: приёмку подтверждает только владелец.
